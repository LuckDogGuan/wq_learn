## 一、帖子要点（三层架构）

1. **数据收集与清洗（ETL）**：Playwright 模拟登录 + SSO 增量爬取论坛 → Markdown（文件名记录时间/点赞/评论/Post ID）→ 动态阈值过滤（近 1 月新帖「点赞或评论 ≥5」保留；1 月前历史帖「<10」双向过滤）→ Gemini Flash 做「痛点驱动」原子化 QA（真实报错设为 Question、自动补平台黑话提升 BM25 命中）。
2. **向量化语义入库**：BAAI/bge-small-zh-v1.5（512 维中文向量）+ LanceDB 混合检索（BM25 + 向量）；「代码保护型 Markdown 切块」在代码块内严禁切分；官方/社区双表隔离（wqb_official_guides / wqb_forum_experiences）。
3. **MCP 服务（FastMCP）**：两个工具 search_wqb_official_guidelines（最高优先级）/ search_wqb_forum_experience（次高优先级）；「极致懒加载」避免 MCP 握手超时；检索采用「前 7 核心 + 随机扩充」动态采样；命中后从 filter_post/ 读回完整原文。

## 三、可直接采纳的要点 → 路线④落点

- **极致懒加载**：路线④任何新增 MCP 工具/知识服务（含 forge dsh-brief 简报生成器）若引入重型依赖（模型/大库），必须惰性加载，禁止在进程启动阶段同步加载，规避 MCP 客户端 10s 握手超时误判。
- **代码保护切块 + 全文反查**：ExperienceReuser 生成经验卡（≤3.8KB）与 DSH 简报时，含代码/表达式的条目按代码块边界切分、不硬切；卡片只放摘要，命中后回读完整原文。
- **动态采样**：多候选注入时「核心命中 + 随机扩充」混合，避免只回放同一批历史案例。
- **双源隔离**：与 knowledge_priority_80_20 完全一致，无需改动，普通论坛资料仅 20% 兜底使用。

## 五、与路线④红线的兼容性

- 不涉及回测/提交：全部为只读知识检索，不违反 D1-Only、禁用算子、零 /submit、并发上限、MemoryMax=512M、无本地 Web GUI 等红线。
- MCP 知识服务不是本地 Web GUI；若落地为后台常驻服务，仍须遵守「SQLite WAL Checkpoint / 10m 认证刷新 / 10s 重连 / 流式低内存扫描」与地区并发上限。
