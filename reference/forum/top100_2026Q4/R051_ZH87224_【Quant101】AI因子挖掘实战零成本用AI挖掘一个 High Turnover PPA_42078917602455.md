# 【Quant101】AI因子挖掘实战：零成本用AI挖掘一个 High Turnover PPA

以往的 PPA 主题大多是配置型 Alpha——只要因子满足 Universe、Neutralization、Dataset 等配置项，就可以确保符合主题要求。但本次 PPA 是 **表现型 Alpha** ：除了 Region/Univ 必须满足 USA-TOP1000 之外，还要求 Turnover > 20%，并且必须通过 High Turnover returns ratio test。

这意味着因子是否符合主题，只有做出来之后才能验证。从这个角度来说，本次主题的难度比以往要大得多。

下面我们用 AI 完整走一遍流程，从零挖掘一个符合主题的 PPA。

## Step 1：主题分析

先明确主题的硬性门槛，参考官方文档  **Getting Started with High Turnover Alphas** ，核心要求只有两点：

1. **Turnover > 20%**
2. **High Turnover returns ratio test** ： `high-tvr-returns / original-returns > 0.75` ，即收益必须主要来自高换手部分

第二条尤其关键——它确保你的因子不是"碰巧换手率高"，而是 **收益本身就来源于高频交易逻辑** 。

## Step 2：选择数据集

既然要点亮 Options 的塔，我们让 AI 从 USA/D1/Option 类数据集中推荐一个最合适的。

> 我需要做一个 High Turnover 主题，打算从 usa/d1/option 类数据集中选一个来做，请从数据集本身的含义出发分析，告诉我应该选哪个。

### 为什么波动率类不适合 HTVR

波动率数据有一个本质问题： **变化太慢** 。

- 隐含波动率（IV）通常是缓慢漂移的，不会每天大幅跳变
- 历史波动率更是滚动窗口计算的，天然平滑
- 用波动率做出来的信号，turnover 通常偏低，很难达到 >20% 的门槛
- 即使做  `ts_delta(iv, 1)`  这种变化率，信号噪音也很大，Sharpe 很难保证 >2

### 最终推荐

**首选  `order_flow_imb`** ，理由：

1. **订单流失衡 = 日频情绪变化的直接度量** ，信号天生高换手，经济含义最清晰
2. **Value Score 5.0** （Option 类最高）+  **仅 56 个 Alpha** （蓝海）——性价比极高
3. **120 个字段** 按参与者类型细分，可以构造多种高换手策略
4. **Pyramid 1.3x × HTVR 3.0x = 3.9x 乘数叠加**

- 243 个字段挖掘空间更大
- 同样 Value Score 5.0、仅 53 个 Alpha
- 但覆盖率偏低（74.9%），需要注意 NaN 处理

## Step 5：筛选有信号的因子

从回测结果中按以下条件筛选候选因子：

- Turnover > 0.15（留出余量，目标是 >20%）
- PnL 趋势正常，无明显断裂或衰减
- PPA-Corr < 0.5（与现有 PPA 因子相关性低）
- 操作符数 < 10
- 字段数 < 4

筛选出的优质因子将作为全自动挖掘的起点。

### 评论 #3 (作者: FF45555, 时间: 2个月前)

楼主用 order_flow_imb 做 High Turnover PPA 的思路很清晰，opt 类字段天然高换手确实是最优解。补一个用 order_flow_imb 时容易被忽略的坑： **coverage 80.92% 导致的"被动换仓"污染 turnover。**

**期权数据的特征就是 coverage 非 100%。**  楼主也提到了 coverage 80.92%——这意味着日均约有 2-3 只票当天没有 option order flow 数据。当某天没数据的票突然复档有数据，信号从 NaN 跳到某个 rank 值，你的持仓被迫做一次"纠偏式换仓"——这和你的信号强度无关，是被缺数据逼出来的机械调仓。我实测 USA/TOP1000/D1 上类似 coverage 的 alpha， **被动换仓能占到总 turnover 的 5-8%** ，而这是 noise turnover，在 OS 上只会拉低净 sharpe。

**怎么区分真实 vs 被动 turnover：**  把 alpha 的 daily position change 拆成两部分——有信号变化的票（正常换仓）vs 信号从 NaN 变有效的票（被动纠偏）。如果后者占比 >5%，考虑对缺失段用 ts_backfill 短窗（3-5 天）或加一个 minimum trade days 门控。order_flow_imb 这种 coverage 本身就是一种"信号"，别让它被缺失段给污染了。

接楼主：High Turnover returns ratio 要求收益必须来自高换手——但如果一部分 turnover 是被 coverage 断档"逼"出来的，这部分收益就不是"真实高频交易收益"，ratio test 可能会被污染。

### 评论 #7 (作者: ZC81788, 时间: 2个月前)

感谢分享。我按同一套「高换手选题 → 模板回测 → 筛信号 → 优化」跑了几轮 USA TOP1000 的 High Turnover，HT 相关门槛（TO>20%、returns ratio 等）多数能过，但在「高换手本身」上感觉工作流还有几处局限，补充如下：

**1. 「天然高换手」选题，容易停在「能做出高 TO」，而不是「高 TO 带来的收益够厚」** 

原帖硬门槛很清楚：Turnover>20%，且 high-tvr-returns / original-returns > 0.75（收益要真来自高换手逻辑）。流程在选日频快变数据、做出高 TO、过 ratio 上很有效。

但实操里常见情况是：TO 和 ratio 都过了，Returns 仍然偏薄。高换手下 Fitness 大致受 Sharpe×√(|Returns|/TO) 约束——TO 高会直接压 Fitness。工作流如果主要以「过 HT 检查」为验收，会系统性低估「收益厚度」这一维。

**2. 高 TO 与可提交性存在目标张力，流程里缺少早期止损** 

HT 需要换手够高；账号侧又常卡 LOW_SHARPE / LOW_FITNESS。短记忆、日频情绪/流量类信号天然容易高 TO，但也容易「换手有了、margin 不够」。模板期若只筛 TO>0.15 或 |Sharpe| 过线，会把大量「高换手但赚不动」的结构送进优化期，用 decay/平滑再往下拧 TO 时，还可能伤到 ratio（过度平滑后不像「收益来自高换手」）。

**3. 字段验真偏弱时，会把「假高 TO / 假高分」当成 HT 赢家** 

表现型主题本就「做出来才知道合不合规」。若字段是稀疏 VECTOR 或有效历史很短，IS 上仍可能刷出高 TO + 高 Sharpe，但分年 PnL / 2Y 会穿帮。工作流若在模板阶段不强制看字段类型、有效覆盖年份，优化会围绕不可持续的高换手假信号打转。

**4. 高换手 alpha 的表现，最终仍很大程度取决于数据字段本身的质量** 

即便流程能稳定做出 TO>20% 且 ratio 合格的因子，Sharpe / Fitness / margin 的天花板仍主要受字段信息含量、覆盖完整性、更新频率与经济含义约束。换模板、拧 decay、做参数扫描往往只能在既有字段质量附近微调，很难单靠「高换手工作流」把薄信号做成厚收益。因此选题阶段除了「是否容易做出高 TO」，还需要同步判断字段是否具备支撑高换手收益的质量基础。

**一句话** ：这套工作流很适合 **稳定做出并验证 High Turnover 主题合规** ；局限在于对「高 TO 下的收益质量 / ratio 与 Fitness 的权衡 / 字段全历史有效性与字段质量」约束偏软，容易得到「HT 全绿、但高换手赚得不够厚」的因子。若目标不仅是过主题、还包括可提交强度，建议在选题和模板入围就加上收益厚度与字段质量验真，而不是只优化到 TO 和 ratio 过线。

- `PROD_CORRELATION < 0.7` 、 `SELF_CORRELATION < 0.7`

**3X 子主题（在基础 2X 之上任命中一个即可）**

- Liquid： `HT_LIQUID_TOPDIV3000_SHARPE >= 1.7` 。 **这条最容易被误解** ——它是把你的 alpha 放到 TOPDIV3000 子域上重算 Sharpe，跟你自己回测用的 universe 无关。我手上一条  `universe=TOP3000`  的 alpha 照样 PASS 了 Liquid，所以不必为了这个主题去改 universe。
- Investable： `HT_INVESTABLE_MAX_TRADE_SHARPE >= 2.0`  且  `MAX_POSITION_SHARPE >= 2.0` ，两条都要。
- Orthogonal： `HT_ORTHOGONAL_RAM_NEUTRALIZATION == "RAM"` ，也就是 neutralization 选  `REVERSION_AND_MOMENTUM` 。 **这是唯一不附加任何 Sharpe 门槛的 3X 子主题** ——只要基础 2X 过了，改个中性化参数就白拿 3 倍，性价比最高，建议大家优先试。

另外一个反直觉的观察：我扫了自己库里 1100+ 条 GLB alpha， `ht_ratio >= 0.75`  的有 244 条，其中同时满足  `S>=1.7 & F>=1.0 & Tvr>=0.2`  的有 51 条，最高 Sharpe 到 3.11。 **所以「高换手就一定低 Sharpe」是个假墙** ，我之前被一份旧缓存（只有 800 条、最高 S=1.24）骗了两天。真正卡死我的是 PROD_CORRELATION：这 51 条全部出自同一个数据集家族，PC 挤在 0.80~0.85 下不来。

顺手记一条踩坑：低 PC 的独立弹药（我用的是全部 ac=0 的图像类字段）确实能把 PC 压到 0.55~0.60，但那一族的 Sharpe 天花板只有 1.7 左右、Fitness 上不了 0.6，单腿没法用；而且同族内 ht 越高 Sharpe 越低，是硬张力。所以我现在的路线是拿它当稀释腿去救主线的 PC，而不是当主腿。有做过类似「低 PC 外源腿稀释」的同学，欢迎交流权重区间的经验。
