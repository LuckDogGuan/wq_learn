## 帖子正文

**概述：**  各位顾问在提交Power Pool Alpha时，想必都清楚平台对单个地区每月 **纯PPA（Pure Power Pool Alpha）有10个的上限** 。但更棘手的是，目前平台存在一个 **隐蔽的Bug** ：如果某个地区当月已提交满10个纯PPA，那么 **整个当月都无法在该地区提交任何新的PPA** ，即使是那些同时符合ATOM或Regular要求的PPA也会被拒之门外！

这意味着，每次提交前我们都需要手动检查该地区已提交的纯PPA数量，否则就可能浪费一次宝贵的提交机会。手动检查不仅繁琐，还需要消耗一次API请求配额。

为此，我分享一个  **“开袋即食”的Python脚本** ，它能一键自动统计你 **当月在各地区已提交的纯PPA数量** 。你可以根据打印结果，清晰地调整后续的提交策略，避免撞上上限和Bug。

## 工具核心功能

1. **登录** ：完成平台认证。
2. **智能日期范围** ：自动获取当前月份（如2026-04-01至2026-05-01）作为查询区间。
3. **并发高效获取** ：使用多线程并发请求，快速拉取当月所有已提交的Alpha数据。
4. **精准识别纯PPA** ：
   - **有  `POWER_POOL`  分类**
   - **没有  `REGULAR`  分类**
   - **不是  `ATOM`  类型** （通过检查是否包含  `SINGLE_DATA_SET`  等标识）
5. **分地区统计** ：按地区（如USA, EUR, ASI, GLB, AMR等）分别统计并打印纯PPA数量。

## 代码使用说明

直接将以下代码保存为  `.py`  文件，并补全代码中的username和password字段，运行即可。

```
"""纯PPA数量统计工具用于统计各地区纯PPA（Power Pool Alpha）的数量"""import requestsfrom requests.auth import HTTPBasicAuthfrom datetime import datetimefrom time import sleepimport concurrent.futuresfrom tqdm import tqdmdef sign_in():    username = ''    password = ''    sess = requests.Session()    sess.auth = HTTPBasicAuth(username, password)    sess.post('https://api.worldquantbrain.com/authentication')    return sessdef get_current_month_dates():    """    获取当月初和下月初的日期       Returns:        tuple: (当月初日期, 下月初日期)，格式为 'YYYY-MM-DD'        例如: ('2026-04-01', '2026-05-01')    """    # 获取当前日期    now = datetime.now()       # 当月初日期    current_month_start = datetime(now.year, now.month, 1)       # 下月初日期    if now.month == 12:        next_month_start = datetime(now.year + 1, 1, 1)    else:        next_month_start = datetime(now.year, now.month + 1, 1)       # 返回格式化后的字符串    return current_month_start.strftime('%Y-%m-%d'), next_month_start.strftime('%Y-%m-%d')def get_url(s, url, relogin=False):    """发送GET请求并处理重试逻辑"""    _s = s    count = 0    status_fail = 0    while True:        if(count > 1800 or status_fail > 10):            print(f"\033[31mget{url}超时\033[0m")            return {}        try:            resp = _s.get(url, timeout=60)            if('Retry-After' in resp.headers):                count += 1                sleep(float(resp.headers['Retry-After']))            elif resp.status_code == 200:                return resp            else:                status_fail += 1                print(f"get {url} Error: {resp.status_code}")                do_reLogin = relogin and resp.status_code == 401                if do_reLogin:                    s = sign_in()                    _s = s                elif resp.status_code == 404 or resp.status_code == 401:                    return {}        except Exception as e:            print(e)def fetch_and_process_url(s, url, output):    """获取并处理URL数据，直接返回原始alpha"""    count = 0    while True:        try:            if count > 10:                print("放弃获取")                return            response = s.get(url, timeout=60)            alpha_list = response.json()["results"]            for alpha in alpha_list:                # 过滤掉已下架的alpha                if alpha.get('status') != 'DECOMMISSIONED':                    output.append(alpha)            return        except Exception as e:            print(e)            count += 1            sleep(15)def get_alphas(s='', start_date='', end_date='', getSubmitted=False, type='REGULAR'):    """获取alpha列表"""    dateStr = 'dateCreated'    if getSubmitted:        dateStr = 'dateSubmitted'       if not s:        s = sign_in()       output = []    urls = []       url_template = (        "https://api.worldquantbrain.com/users/self/alphas?limit=100&offset={x}"        f"&status{'!' if getSubmitted else ''}=UNSUBMITTED%1FIS_FAIL"        f"{f"&type={type}" if type else ''}"        f"{f"&{dateStr}%3E={start_date}T00:00:00-04:00" if start_date else ''}"        f"{f"&{dateStr}%3C{end_date}T00:00:00-04:00" if end_date else ''}"    )       alpha_count = 1    data_result = get_url(s, url_template.format(x=0), True)    alpha_count = data_result.json()['count']    print(f'共有{alpha_count}条数据')       for x in range(0, alpha_count, 100):        urls.append(url_template.format(x=x))       with concurrent.futures.ThreadPoolExecutor() as executor:        futures = [executor.submit(fetch_and_process_url, s, url, output) for url in urls]        for _ in tqdm(concurrent.futures.as_completed(futures), total=len(futures), desc="Get URLs"):            pass       print("count: %d" % len(output))    return outputdef get_pure_ppa_count(s):    """    统计各地区纯PPA数量    纯PPA定义：有POWER_POOL分类，没有REGULAR分类，且不是atom类型的alpha       Args:        s: 登录会话对象    """    start, end = get_current_month_dates()    alphas = get_alphas(s, start_date=start, end_date=end, getSubmitted=True)    regions = list(set([item['settings']['region'] for item in alphas]))       for region in regions:        region_alphas = [item for item in alphas if item['settings']['region'] == region]        pure_ppa_count = 0               for alpha in region_alphas:            # 提取所有classification的id            classification_ids = [cls['id'] for cls in alpha['classifications']]            # 检查是否有POWER_POOL项且没有REGULAR项            has_power_pool = any('POWER_POOL' in cls_id for cls_id in classification_ids)            has_regular = any('REGULAR' in cls_id for cls_id in classification_ids)                       # 内联 is_atom 逻辑            has_atom = False            if 'classifications' not in alpha:                print('\033[31m缺少分类信息\033[0m')            else:                has_atom = sum(1 for item in alpha['classifications'] if any(l for l in ['SINGLE_DATA_SET'] if l in item['id'])) > 0                       if has_power_pool and not has_regular and not has_atom:                pure_ppa_count += 1               print(f"{region}地区纯PPA数量: {pure_ppa_count}")if __name__ == '__main__':    # 主程序入口    s = sign_in()    get_pure_ppa_count(s)
```

## 如何根据结果制定提交策略？

看到统计结果后，你可以立刻做出明智决策：

1. **数量已达10个的地区（如示例中的EUR）** ：
   - **警惕！**  本月无法在该地区提交 **任何** 新的PPA（包括PPA+ATOM或PPA+Regular）。
   - **策略** ：立即将开发重心转移到其他未达上限的地区。
2. **数量接近10个的地区（如示例中的USA有8个）** ：
   - **谨慎规划** ：剩余额度不多，优先提交你认为质量最高、最有把握的纯PPA。
   - **考虑混合提交** ：如果想继续在该地区提交，可以转向开发  **`[Power Pool + ATOM]`**  或  **`[Power Pool + Regular]`**  类型的Alpha，它们 **不受此月度限额约束** （但需遵守各自的提交标准）。
3. **数量较少的地区（如ASI、GLB）** ：
   - **机会所在** ：仍有充足额度，可以放心规划和提交高质量的纯PPA。
4. **数量为0的地区（如AMR）** ：
   - **蓝海市场** ：完全可以作为本月的主攻方向之一。

## 注意事项与进阶建议

### 评论 #6 (作者: LP42537, 时间: 2天前)

这篇我之前跑过，挺好用的。不过得提醒一句，官方 9/22 刚改了配额口径，帖子开头"每个地区每月 10 个纯 PPA"这个模型现在不一样了，脚本本身也要跟着调，不然容易给自己算错额度。新规则是按你第一个纯 PPA 的提交时间来分级：头两周 4 个/天、3-4 周 2 个/天、5-6 周 1 个/天，这三段都没有月度上限；满 6 周之后变成 1 个/天，而且每个自然月每个 scope 只能有 10 个纯 PPA，还要求匹配一个在跑的 Power Pool Theme，不匹配会被拒，报错是 "Pure Power Pool submission does not match any Power Pool Theme"。如果你第一个纯 PPA 是 90 天以前交的，这个分级表不适用，直接就是 1 个/天加每月每 scope 10 个。真正影响脚本的是 scope 的定义，不再按 region 分了：USA 的 D0 和 D1 合成一个 scope，EUR 的 D0 和 D1 一个，ASI 只有 D1，GLB 只有 D1，剩下的 JPN/CHN/HKG/TWN/KOR/AMR/IND 的 D0、D1 全部挤在同一个 scope 里。所以按 settings['region'] 统计那一层得改，不然 AMR 看着是 0，其实它和 JPN、CHN 在抢同一个 10。代码里还有几处我顺手记了一下。get_current_month_dates() 用的是 datetime.now()，也就是本机时间，但筛选条件是美东月界。月初北京时间 0 点到 12 点之间跑的话，脚本已经翻月、平台还没翻，结果会偏小，而这恰好是最容易误判的时候。而且 -04:00 是夏令时的写法，冬天得用 -05:00，建议直接上 ZoneInfo("America/New_York")，把三处硬编码一起解决。分页那段 fetch_and_process_url 没有复用 get_url()，撞上 429 或者 401 时重试 10 次会直接 return，那一页 100 条就静默丢了，最后只打印一个 count，你拿到的是偏小的数，还以为是安全的。建议跟前面的 alpha_count 对不上就直接抛错，宁可跑挂也别悄悄少算。还有 if alpha.get('status') != 'DECOMMISSIONED' 这一行：本月提交过、后来下架的 PPA 是不是照样占额度，我不太确定，你验证过吗？如果占，这里就漏了。评论区 LH81305 说的"先交了纯 PPA，当天就交不了 PPA+ATOM"，按新口径更像规则本身（满 6 周后就是 1 个/天），不一定算 bug，但提交顺序确实有讲究。你这个脚本顺手把"今天交了 0 个""这个 scope 本月还剩几个"也打印出来，用起来会更省心。
