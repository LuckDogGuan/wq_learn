## 帖子正文

由于种种原因的限制，worldquant官方各类培训视频中涉及到的的源代码有时候并不会直接完整地分享给各位顾问，只会在视频中给大家展示。当我们录制完课程视频想要复刻视频中的代码的时候，还要花时间先把代码从视频中提取出来。

以前本人曾经心血来潮地将整个视频文件扔给了Gemini让它读取，它跳出来的第一句话是不支持直接读取视频，直接拒绝了我的请求。

最近本人在尝试使用Codex，把相同的任务扔给了Codex之后，它虽然也不支持直接读取视频，但它自己构建了一整套完整的从视频中提取关键帧/截图/OCR辅助识别/代码重建的完整的skill，并用这套skill完美的从多个官方webinar视频中提取到了代码。在这里直接把skill分享给大家。

这个skill的工作流程如下：

> 1. **视频检测**
> 读取视频的时长、帧率、总帧数及分辨率，确认文件和编码是否可以正常解析。
> 2. **建立视频导航图**
> 按固定间隔抽取画面，并生成带时间戳的联系表（Contact Sheet），快速识别代码编辑器、终端及 Notebook 所在区段。
> 3. **提取证据帧**
> 在代码滚动、输入、窗口切换或光标遮挡的位置增加采样密度，保留分辨率较高且内容完整的画面。
> 4. **图像预处理**
> 裁剪代码区域，并通过高质量插值放大两到四倍，以提高小字体、低码率视频中的字符可读性。
> 5. **OCR 辅助识别**
> OCR 仅用于生成初稿。最终内容仍需对照原始画面，重点检查引号、括号、下划线、缩进，以及  `1/l/I`  等易混淆字符。
> 6. **代码重建**
> 合并多个画面中的重叠代码，删除重复内容，并保留导入语句、装饰器、函数签名、注释和 Notebook 单元格边界。不可见内容不会被主观补全，而是标记为不确定或  `partial` 。
> 7. **语法验证**
> 对完整代码执行解析或编译检查，排查缩进错误、智能引号、缺失符号及 OCR 产生的异常标识符。
> 8. **结果交付**
> 输出 Markdown 转录文档、独立源代码文件，以及包含验证结果和不确定内容的说明。

```
---name: extract-code-from-videodescription: Recover clean source code from programming videos, screen recordings, webinars, IDE recordings, terminal recordings, notebook walkthroughs, or videos where code appears on screen. Use when Codex needs to extract, reconstruct, OCR, visually transcribe, verify, and package code from a video file or sampled frames, especially when the source files are unavailable and the video contains scrolling or partially visible code.---# Extract Code From VideoUse this skill to recover usable code from a video, not just noisy OCR text. Favor a conservative transcript: verify syntax visually, mark uncertain or hidden lines, and package extracted code into clean deliverables.## Workflow1. Inspect the video:   - Confirm the file is readable.   - Get duration, FPS, frame count, width, and height.   - Check available tools: `ffmpeg`, `ffprobe`, `tesseract`, Python `cv2`, `PIL`, `numpy`, and platform OCR.2. Build a navigation map:   - Sample frames at a coarse interval such as 60-120 seconds.   - Create a contact sheet with timestamps.   - Identify sections that show code, output, browser/notebook views, scrolling, or duplicated holds.3. Extract evidence frames:   - Save full-resolution frames around each code section.   - Add denser sampling around fast scrolls, cursor occlusions, typing, or section changes.   - Prefer frames where the cursor, selection highlight, or presenter overlay does not obscure characters.4. Improve readability:   - Crop only the code pane or notebook cell.   - Enlarge crops 2x-4x with high-quality resampling.   - If text is tiny or blurred, compare several adjacent frames; compression artifacts differ by frame.5. Use OCR as a draft, not truth:   - OCR is useful for identifiers and prose but often corrupts `=`, `_`, quotes, brackets, `1/l/I`, and indentation.   - Correct OCR against the visible syntax.   - Use language knowledge only for cleanup that is strongly supported by the frame; do not invent hidden code.6. Reconstruct code:   - Merge overlapping snippets from multiple frames.   - Deduplicate repeated holds.   - Preserve imports, constants, function signatures, decorators, comments, and cell boundaries when visible.   - For notebooks, distinguish executable code, output, and explanatory markdown.   - Mark cut-off snippets as `partial` or add a clear placeholder such as `...` with a comment.7. Validate:   - Run syntax checks on standalone source files when imports do not require unavailable services.   - If imports require private packages, use `py_compile` only when the code can parse without importing dependencies.   - Confirm no copied OCR garbage remains: scan for impossible identifiers, smart quotes, missing punctuation, and broken indentation.8. Deliver:   - Save a full transcript as Markdown with sections and fenced code blocks.   - Save standalone `.py` files for complete runnable snippets.   - Mention what was verified and what remains partial or uncertain.## ScriptUse `scripts/video_code_sampler.py` to inspect a video, make contact sheets, save timestamped frames, and create enlarged crops.Examples:```powershellpython scripts/video_code_sampler.py inspect --video "D:\path\video.mp4"python scripts/video_code_sampler.py contact --video "D:\path\video.mp4" --every 120 --out work/video_extract/contact.jpgpython scripts/video_code_sampler.py frames --video "D:\path\video.mp4" --times 240,360,480 --out work/video_extract/framespython scripts/video_code_sampler.py crop --image work/video_extract/frames/frame_0240.png --box 150,300,1825,920 --scale 3 --out work/video_extract/crop.png```## Practical Heuristics- Long videos often repeat the same screen for minutes; use the contact sheet to skip duplicates.- The final source-file view is usually more reliable than a markdown preview or live typing frame.- Browser/notebook sections may contain both code and output; extract the code cells separately from results.- If a code block scrolls off before completion, sample more densely around that time before declaring it partial.- If online search is allowed and useful, search exact titles, filenames, and distinctive code phrases for the original source; use only reliable matches.- Keep all raw frames/crops in a work directory and only publish cleaned deliverables.## Output StandardEvery final extraction should include:- A Markdown transcript with all recovered snippets.- Separate source files for complete programs or modules.- A short note listing syntax checks run and any partial/uncertain sections.
```

### 评论 #3 (作者: HH34943, 时间: 2个月前)

这套用  **Custom Skill 自动化提取视频代码**  的思路简直绝了！

官方培训视频里经常遇到那种“导师讲得激情澎湃，关键代码一闪而过，全篇 PPT 和回放里就是不给你完整源码”的恶心情况。以前遇到这种局，要么自己抱着键盘一帧一帧暂停手动敲，要么像楼主最开始那样把大文件直接丢给 AI，然后被一句“不支持直接读取视频”硬控在原地。

用 Codex 现场编写一套包含“关键帧抽取 + 图像预处理 + OCR 辅助识别 + 代码重建 + 语法验证”的完整工作流 Skill，相当于直接给 AI 赋予了一个“具备计算机视觉和 OCR 能力的自动化视频助教”。

这套工作流里面有几个设计极其精妙：

1. **动态采样密度：**  不是弱智似地每隔固定几秒切一帧，而是会捕捉“代码滚动、输入、窗口切换”的动作密度来加采样。这极大地减少了无效画面的算力浪费。
2. **OCR 只作初稿：**  懂行的都知道，直接用 OCR 识别代码简直是灾难（各种全角半角引号、 `1/l/I` 、下划线混淆）。它把 OCR 定位为“初稿生成器”，最后必须结合上下文和语法验证去排查修复，这保证了最终输出代码的可用性。
3. **不可见内容不主观补全（Mark as partial）：**  这点对写代码太重要了。宁可标记不确定，也绝对不让大模型凭空幻觉去瞎编补全逻辑，避免跑出灾难性的 Bug。

把这种多模态处理和复杂工具链封装成一个标准的 Skill，以后再遇到官方那些藏着掖着的 Webinar 回放，直接丢进去跑一轮，几分钟就能把干净的  `.py`  或者  `.ipynb`  源码吐出来。

感谢大佬无私分享这个重磅级生产力工具，这就去研究怎么把这套  `extract-code-from-video`  的 Skill 架构移植到自己的开发环境中去！

### 评论 #4 (作者: QW94165, 时间: 1个月前)

这份 skill 的整体思路很扎实，OCR 只当草稿、不可见内容标  `partial`  这两点正是从视频复原代码时最关键的。

几个可以继续打磨的方向，供你参考：

1. 在交付物里加一段“视频时间戳 ↔ 代码片段”的索引，评论里也提到了，复核引号、缩进和缺失行时能直接跳回对应帧，省去反复手动定位的时间。

1. `video_code_sampler.py`  当前是按固定秒数抽帧，遇到代码区被长时间静止画面跳过时容易漏掉。可以在  `make_contact_sheet`  里加一个相似度判断，相邻缩略图差异小于阈值就跳过，从而把采样密度自动集中到有代码切换的区段。

1. `parse_box`  只校验了元素个数，没有检查  `left<right` 、 `top<bottom` ，命令行误传参数时会直接传给  `PIL.Image.crop`  报错。可以在这里加一道范围和顺序校验，给出更明确的提示。

另外想确认一下： `frames`  子命令目前是按指定秒数精确取一帧，如果代码是连续滚动的，单帧可能刚好落在两行之间被截断，这块在你实际跑官方 webinar 时出现过明显漏字的情况吗？
