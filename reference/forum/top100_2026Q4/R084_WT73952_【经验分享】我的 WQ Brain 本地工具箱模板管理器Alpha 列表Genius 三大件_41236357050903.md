## 帖子正文

```
最近把自己日常用的三个本地工具整合在了一起，分享给受同样问题困扰的顾问。为什么做这三样东西模板管理器是我一直在研究的东西，属于长期的方向。而 Alpha 列表和 Genius 这两个功能，做它们的直接契机是——华子哥的插件部分功能失效了。他的插件很好用，但依赖 WQ 网站运行，最近一次 WQ 前端更新后，部分功能不再正常。加上 WQ 网站本身在浏览器里非常消耗内存，列表里频繁筛选、检测等操作后，内存会莫名其妙地泄露，用久了越来越卡。所以决定把这些功能移植到本地，一个更轻量、可控的环境里。Alpha 列表在原插件的基础上增加了一些功能，Genius 则基本是移植。下面逐个说说。---一、模板管理器这是整个工具链的起点。核心思路是：论坛文章驱动 + LLM 辅助 + 批量回测。模板来源模板不是凭空写的。我写了一个自动化流程：- 从论坛批量读取未读文章- 把文章内容发给 LLM，让它提取文中的 alpha 表达式 pattern- 如果 pattern 包含至少 2 个算子（`ts_` 或 `group_` 开头的操作），就自动录入到本地的 SQLite 模板库- 每条模板会记录来源（哪篇文章）、算子数、字段类型（MATRIX/VECTOR）、逻辑描述目前库里积累了上百个从论坛文章提炼出的模板，覆盖了动量、反转、波动率、基本面等各种类型。变体管理一个基础模板下可以创建多个变体。同一个 alpha 逻辑，稍作调整就能衍生出不同版本：- 换一种中性化方式（`group_neutralize` by sector vs by subindustry）- 换时间窗口（`ts_mean(F, 20)` → `ts_mean(F, 40)`）- 加一层 `zscore`、`winsorize` 或其他算子变体继承模板的字段占位符 `{F}`，各自独立保存，方便对比和批量提交。LLM 扩展选中一个模板，点"模板扩展"，本地后端会把以下信息打包发给 LLM：- 模板的 pattern 和逻辑描述- 算子参考手册（所有 WQ 算子的说明和用法）- 指定 region 的可用数据集清单LLM 分析后返回：- 信号周期评估：这个 pattern 适合短/中/长哪个周期- 适用数据类型：价格类、基本面类、还是另类数据- 扩展模板：基于原始 pattern 推荐多个变体，比如换归一化方式、换分组方式、叠加其他算子扩展结果可以一键保存，变体自动添加到模板下。一条基础 pattern 经过扩展后可以很快衍生出十几个有差异化的变体。批量匹配与回测选定一批模板 + 指定 region + 数据集后：1. 模板的 `{F}` 占位符替换为实际数据集字段2. 生成完整的 alpha 表达式3. 批量提交到 WQ Brain 回测4. 结果入库，后续在 Alpha 列表页面查看当前局限这个模块还在迭代中，目前整个流程处于测试阶段，并不能做到稳定产出。几个明显的不足：- 只支持单字段模板（一个 `{F}`），还不支持多字段组合或通配符- 编辑器没有实时校验，表达式是否合法只有提交回测前才做检查，编辑时看不到语法/格式错误---二、Alpha 列表这个页面移植自华子哥的浏览器插件。他的插件功能很实用，但依赖 WQ 网站运行，最近一次 WQ 前端更新导致部分功能失效了，加上 WQ 网站本身访问和响应速度偏慢，所以决定把 Alpha 列表移植到本地纯净环境里，在原来的基础上增加了一些功能。1. 指标高亮每个 Alpha 的各项指标（Sharpe、Fitness、Turnover、Margin 等）做了颜色区分——合格的标一种颜色，不合格的标另一种，一眼扫过去就能知道哪些 Alpha 各项指标都在线，哪些有问题。2. Fail 计数明细把所有的 WARNING/FAIL 汇总成一个 fail 总数，鼠标悬停可以看到每项的具体状态。对于那些接近合格线**的 fail 指标，用箭头（↑/↓）标注出来，提示方向，方便决定要不要优化。3. 颜色管理绿/黄/红/蓝/紫/灰多色支持，可以批量标色，适合在大规模 Alpha 池里做分类管理。4. Prod Correlation 缓存每个 Alpha 的 prod corr 数据拉到浏览器 localStorage，刷新页面不会丢，只有手动点击才会重新计算。对做相关性筛选的场景来说，不需要每次打开页面都重新请求一遍。5. 筛选条件持久化刷新页面不会清空筛选条件——因为大多数时候只是微调一两个筛选条件，而不是从头开始。6. 筛选项按 Sharpe、Fitness、Turnover、Margin、颜色、状态、算子等十几个维度组合筛选。---三、Genius 排名分析Genius 页面基本上移植了 WQ 网页端和华子哥插件的功能，核心好处是缓存：排名数据和操作符分析拉取后缓存在本地，刷新页面直接读缓存，只有主动点击时才重新拉取。不用每次打开都等 WQ 那边响应。页面把 Genius 各维度的得分（Sharpe、Turnover、Fitness、Margin等）展开成表格，同时显示当前分和目标分，短板在哪里、离下一级还差多少，一目了然。
```

### 评论 #1 (作者: AF24600, 时间: 3个月前)

感谢楼主分享完整工具链！这和我最近用 Claude Code + BRAIN MCP API 搭的"AI-native 工具箱"思路高度吻合，补充几点实测：

**LLM 扩展输入的共鸣**

我的  `alpha-machine-skill`  也是把 pattern + 算子手册 + 数据集清单三件套打包给 LLM（和楼主"模板扩展"模块的输入完全一致），产出变体。实测发现 LLM 的信号周期评估整体靠谱——波动率类信号几乎都被归为短周期，基本面类归为长周期，但偶尔会推荐实际不存在的算子名（如  `ts_ema` ），需要对着算子清单做一轮校验再提交。

**批量回测的最大瓶颈**

BRAIN multisim 每批限制 8 个表达式，LLM 一次推荐 10~20 个变体时必须拆批轮转（今天实测：2 批 ×2 + 1 批 ×8，加上 SLOW 中性化的运算耗时，完整跑完一个 idea 的参数空间要等 15~20 分钟）。请问楼主的批量提交模块有没有做自动分批？还是手动控制每次提交数量？

**单字段  `{F}`  的局限**

我这边也停在单占位符，多字段（如  `ts_corr({F1}, {F2}, 20)`  类的配对信号）目前的临时解法是两个字段分开跑一阶，再手动配对写表达式——效率确实不高。有没有考虑过  `{F1}` / `{F2}`  的扩展方案？

### 评论 #8 (作者: XW23690, 时间: 3个月前)

三个工具都很实用，尤其是模板管理器——从论坛文章自动提取 pattern 这个思路很高效。几个想法：

1. 模板管理器目前只支持单字段模板（一个 {F}），这个限制确实比较大。很多高质量 alpha 都是多字段组合的（比如 ts_corr(field1, field2, d)），如果能支持多字段占位符 {F1}、{F2}，模板的覆盖面会大很多

3. 模板的 LLM 扩展功能可以和 brain-forum-browse skill 结合——在浏览论坛时自动识别新模板，实时录入到本地库，这样模板库会自动增长

4. 编辑器没有实时校验这个问题，可以考虑用正则表达式做简单的语法检查（比如括号匹配、算子拼写），虽然不能完全替代正式校验，但能提前拦住大部分低级错误
