## 帖子正文

GEMINI-cli在6月18号就不能使用了，需要迁移到Antigravity CLI，但是配置mcp提示：

> ✗ worldquant-brain-platform error: calling "initialize": invalid character 'r' looking for beginning of value

这个错误表明  `worldquant-brain-platform`  MCP 服务器在初始化时返回了无效的响应。 `invalid character 'r' looking for beginning of value`  通常意味着 MCP 服务器返回了非 JSON 格式的输出（可能是纯文本错误信息）

是由于MCP platform的程序中有打印：

```
    print("running the server")  # ← 这行输出到 stdout，破坏了 JSON-RPC 协议！
```

不建议修改  `platform_functions.py，后续更新了会完全覆盖，导致修改失效。`

`所以可以新建一个 wqb_mcp_wrapper.py `  `脚本来处理这个问题，同时修改mcp的配置`

import sys
import os
import runpy

# 保存原始 print
_original_print = print

def filtered_print(*args, **kwargs):
    """替代 print 函数，将输出转到 stderr"""
    kwargs['file'] = sys.stderr
    _original_print(*args, **kwargs)

# 替换内置 print（在导入任何模块之前）
__builtins__.print = filtered_print

# 设置环境
os.environ['PYTHONUNBUFFERED'] = '1'

# 把原脚本所在目录加入 sys.path
script_path = r'C:\ProgramData\anaconda3\envs\wqb_env\Lib\site-packages\cnhkmcp\untracked\platform_functions.py'
script_dir = os.path.dirname(script_path)

if script_dir not in sys.path:
    sys.path.insert(0, script_dir)

# 使用 runpy 运行
runpy.run_path(script_path, run_name="__main__")

MCP配置修改如下

{
  "worldquant-brain-platform": {
    "command": "C:\ProgramData\anaconda3\envs\wqb_env\python.exe",
    "args": [
      "C:\ProgramData\anaconda3\envs\wqb_env\wqb_mcp_wrapper.py"
    ],
    "env": {
      "PYTHONUNBUFFERED": "1"
    }
  }
}

最后问题解决：

✓ worldquant-brain-platform  Tools: authenticate, manage_config,

                                get_datasets, +34 more

注意脚本中的platform_functions.py地址和MCP的地址需要替换为用户自己的

### 评论 #1 (作者: JG91554, 时间: 3个月前)

现在，不论原始的  platform_functions.py  在初始化还是在执行  create_multi_simulation 、 create_simulation  等写入/核心操作 API  时打印任何干扰文本，我们的  wqb_mcp_wrapper.py  都会拦截并重定向到标准错误流（ stderr ），从而完美保障 JSON-RPC  协议

这个方案非常优雅，即使以后 Python 库版本更新覆盖了  platform_functions.py ， Wrapper
  也完全不受影响。
