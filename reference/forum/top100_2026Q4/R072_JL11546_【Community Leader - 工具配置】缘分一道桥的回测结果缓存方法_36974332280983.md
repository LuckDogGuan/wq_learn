# 【Community Leader - 工具配置】缘分一道桥的回测结果缓存方法

## 帖子正文

### 背景

### 在日常使用缘分一道桥回测时，浏览器不会保存回测的结果，如果不小心关闭了页面或者忘记了之前是否回测过，又得重新跑一遍，非常耗时。

### 解决方案

利用浏览器的 localStorage 功能，可以将回测结果缓存到本地。下次再遇到相同的表达式时，直接读取缓存，无需重复回测。

### 核心实现

#### 1. 添加缓存工具函数（JavaScript 部分）

在 <script> 标签内，添加以下函数：

```
// 生成缓存键function generateSimCacheKey(expression, settings) {    const keyData = {        expr: expression,        region: settings.region,        universe: settings.universe,        delay: settings.delay,        decay: settings.decay || 0,        neutralization: settings.neutralization || 'NONE'    };    return 'yuanfen_sim_' + btoa(JSON.stringify(keyData)).substring(0, 40);}// 保存回测结果function saveSimulationResult(expression, settings, result) {    const key = generateSimCacheKey(expression, settings);    const data = {        alpha_id: result.alpha_id,        sharpe: result.sharpe,        fitness: result.fitness,        turnover: result.turnover,        timestamp: Date.now(),        expression: expression,        settings: settings    };    localStorage.setItem(key, JSON.stringify(data));}// 获取缓存结果function getCachedSimResult(expression, settings) {    const key = generateSimCacheKey(expression, settings);    const cached = localStorage.getItem(key);    return cached ? JSON.parse(cached) : null;}
```

#### 2. 修改渲染变体函数

在渲染每个变体按钮时，检查是否有缓存：

```
// 位置：renderAlphas 或 renderVariants 函数内// 渲染变体时检查缓存variants.forEach(variant => {    const cached = getCachedSimResult(variant.expression, variant.settings);       if (cached) {        // 显示已缓存的结果（绿色/黄色图标）        button.innerHTML = `✅ ${cached.sharpe.toFixed(2)}`;        button.classList.add('cached');        button.onclick = () => window.open(`https://platform.worldquantbrain.com/alpha/${cached.alpha_id}`);    } else {        // 显示待回测状态        button.innerHTML = '⏳ 回测';        button.onclick = () => simulateVariant(variant);    }});
```

#### 3. 修改回测函数

回测完成后保存结果：

```
// 位置：simulateVariant 函数内async function simulateVariant(variant) {    // ... 发起回测请求 ...       const result = await response.json();       if (result.success) {        // 保存到缓存        saveSimulationResult(variant.expression, variant.settings, result);               // 更新页面显示        updateVariantDisplay(variant, result);    }}
```

以后每次在缘分一道桥加载出生成的表达式后如果某个表达式已经回测过就会直接显示结果，避免了重复回测。

### 评论 #3 (作者: LL87164, 时间: 9个月前)

发现两个问题：

1. 中文/特殊字符支持问题： 原代码 btoa(JSON.stringify(keyData))。 在 JavaScript 中，btoa 函数设计之初仅支持 Latin1 字符集。如果Alpha 表达式或注释中包含中文（例如 /* 这是一个策略 */），直接传入 btoa 就会抛出异常，导致缓存功能完全失效。

2. Key 截断问题： 代码在 btoa(...) 后面写了 .substri（看起来是 .substring(...) 的截断写法）。 keyData 的结构是 { expr: ..., region: ... }。由于 Expression（表达式）通常很长且位于 JSON 的最前面，生成的 Base64 字符串的前面大部分都是表达式的内容。 如果对 Key 进行长度截断（比如取前 100 位），那么用来区分不同变体的参数（如 delay、region 等信息）就会被切掉。这就导致同一个 Alpha 的所有变体（比如 delay 0 和 delay 1）生成的 Key 完全一样，从而引发数据冲突。

建议增加 encodeURIComponent 来兼容中文，并去掉 substring 截断

虽然localStorage也可以。但感觉其实不很建议。多了以后，浏览器会很卡的。如果可以，其实更建议保存到IndexedDB下。

**存储大量数据** ：相比 localStorage（通常限制在 5MB 左右）和 sessionStorage，IndexedDB 可以存储显著更多的数据（具体上限由浏览器和用户磁盘空间决定，通常是磁盘空间的很大一部分）
