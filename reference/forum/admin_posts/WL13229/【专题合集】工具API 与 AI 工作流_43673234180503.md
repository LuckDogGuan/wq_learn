这类导航合集的价值在于把所有分散的技巧串成一条可落地的链路,而不是停留在单点工具。我自己的经验是:光有"通知"和"日志"还不够,关键是让它们组成一条不需要人盯的闭环。具体可以分四层:第一层是会话复用,把登录会话缓存做成模块级单例,machine_lib 每次请求复用同一 session,既能避免反复重登被风控,也能减少握手开销,批量回测时差别非常明显;第二层是失败自愈,给批量任务加上"探测-重试-降级"的循环,比如网络中断时不直接抛错退出,而是按指数退避重试并结合时区判断是否错过收盘,这样脚本可以无人值守跑通夜;第三层是通知分级,不把所有事件都推送到手机上,而是把"批量完成+结果汇总"和"异常中断"分成两个通道,连续失败触发的告警要带上前 N 条日志,否则夜里被叫醒也不知道发生了什么;第四层是把版本管理与远程环境结合,用 git 只同步 py 脚本和表达式清单、不同步回测输出,配合 vscode server 做远程开发,顺手解决"本地与云端两套代码漂移"的问题。四个环节里最容易被忽略的是第一层会话复用,很多"回测间歇性 401"其实不是网络问题,而是会话过期后没有统一的重登兜底,值得在启动时做一次健康检查。
