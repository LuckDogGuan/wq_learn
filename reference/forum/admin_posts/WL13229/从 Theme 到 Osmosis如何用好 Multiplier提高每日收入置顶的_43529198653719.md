## 帖子正文

**不分配 Osmosis，就意味着必然落后。**

**不分配 Osmosis，就意味着在最终乘数这一环节停留在 1 倍；面对获得 Osmosis Multiplier>1 加成的研究员，你在这一环节必然落后。**

**先记住这一点：Osmosis 是最后再乘上去的系数。**

同样拥有  **Pyramid Multiplier 2 和 Theme Multiplier 2** ，先算  **2 + 2 − 2 + 1 = 合并倍数 3** ，再比较 Osmosis：

不分配，Osmosis=1： **3 × 1 = 3 倍** 
别人当天 Osmosis=1.8： **3 × 1.8 = 5.4 倍**

注释：这是质量因子倍数的差距， **不是 daily payment 的简单相乘** 。这里比较相同的主题合并倍数；实际支付还受 Alpha 质量、其他因子及相对缩放影响。

**Theme Multiplier 与 Pyramid Multiplier 在合并计算中属于同一类 multiplier。** 下面三个示例都明确展示两个倍数项，因此按“两个倍数相加 − 2 + 1”逐步计算；Osmosis Multiplier 不计入这两个倍数项，而是在合并之后单独相乘。数值 1 表示对应环节没有额外加成。

**小林做对了什么？**

先找到分配给自己的  **2 倍 Theme** ，在活动允许范围内选择  **2 倍金字塔** 对应的字段，做出有逻辑的 Alpha；再认真配置自己的 Alpha 组合。假设当天 Osmosis 系数为 1.8：

**第一步：Pyramid Multiplier 2 + Theme Multiplier 2 − 倍数个数 2 + 1 = 合并倍数 3。** 
 **第二步：合并倍数 3 × Osmosis Multiplier 1.8 = 最终倍数 5.4。** 
完整算式：(2 + 2 − 2 + 1) × 1.8 = 5.4。 **3 倍是合并结果，5.4 倍是再乘 Osmosis 后的结果，不能混为一谈。**

**小周：** Pyramid Multiplier 为 1，Theme Multiplier 为 2，没有分配 Osmosis。先算  **1 + 2 − 2 + 1 = 合并倍数 2** ；再算  **2 × Osmosis Multiplier 1 = 最终倍数 2** 。完整算式： **(1 + 2 − 2 + 1) × 1 = 2** 。

**小陈：** 本例 Pyramid Multiplier 与 Theme Multiplier 都是 1，Osmosis Multiplier 也是 1。先算  **1 + 1 − 2 + 1 = 合并倍数 1** ；再算  **1 × Osmosis Multiplier 1 = 最终倍数 1** 。完整算式： **(1 + 1 − 2 + 1) × 1 = 1** 。

## 02 | 一张公式图，看清 multiplier 加在哪里

**Theme Multiplier 与 Pyramid Multiplier 在合并规则中等同处理：** 把所有实际适用的 multiplier 放入同一个列表，按同一公式计算，不分别合并、更不分组相乘。Pyramid 是按“区域 × 延迟 × 数据集类别”确定的主题加成；官方说明，相关数据使用率越低，其倍数越高，且可能每日变化。

 **第一步 · 统一合并所有适用项** 

**所有适用 multiplier 之和
− multiplier 个数
+ 1**

Theme Multiplier 与 Pyramid Multiplier 采用同一规则。

 **第二步 · 再乘 Osmosis** 

**合并倍数
× Osmosis Multiplier**

Osmosis Multiplier 在 1–2 之间。
不分配为 1；示例取 1.8。

**最终质量因子倍数**

**最终质量因子倍数
=（所有适用 Theme / Pyramid multiplier 之和
− 适用 multiplier 个数 + 1）
× Osmosis Multiplier**

**Osmosis Multiplier 只在最后相乘，不纳入前面的求和，也不计入 Theme / Pyramid multiplier 的个数。**

**合并倍数 = sum(multiplier) − number of multipliers + 1** 
也就是： **所有适用倍数之和 − 适用倍数个数 + 1** 。

只纳入按平台规则实际适用的 Theme Multiplier 和 Pyramid Multiplier；同一项不重复计数。下列多个适用项只是数学演示，不表示任意活动都能同时获得资格。所有例子都明确写出“减去倍数个数，再加 1”，不合并省略。

**不止两个倍数时，也用同一公式。**

**两个适用项：** Pyramid Multiplier 为 2，Theme Multiplier 为 2。倍数个数为 2，所以  **2 + 2 − 2 + 1 = 合并倍数 3** 。

**三个适用项：** 假设实际适用的 Theme / Pyramid multiplier 分别为 2、1.5、1.2。倍数个数为 3，所以  **2 + 1.5 + 1.2 − 3 + 1 = 合并倍数 2.7** 。

若当天  **Osmosis Multiplier 为 1.8** ，再算  **2.7 × 1.8 = 最终质量因子倍数 4.86** 。完整算式： **(2 + 1.5 + 1.2 − 3 + 1) × 1.8 = 4.86** 。

主题合并规则见 [官方问答](/hc/en-us/articles/6675128127511) ；Osmosis Multiplier 的范围及质量因子用途见 [Osmosis 指南](https://platform.worldquantbrain.com/learn/documentation/consultant-information/osmosis-allocation-guide-consultants) 。后乘顺序与“不分配为 1”作为本文补充计算口径，完整来源说明见文末。

### 从 2 倍到 6 倍，变化来自哪里？

**最终质量因子倍数对照** 
不是 daily payment 的简单相乘；以下每行均有两个展示倍数项。

**Pyramid 1× · Theme 2× · Osmosis 1×** 
先合并：1 + 2 − 2 + 1 = 2
再乘 Osmosis：2 × 1 =  **2×**

**Pyramid 2× · Theme 2× · Osmosis 1×** 
先合并：2 + 2 − 2 + 1 = 3
再乘 Osmosis：3 × 1 =  **3×**

**Pyramid 2× · Theme 2× · Osmosis 1.5×** 
先合并：2 + 2 − 2 + 1 = 3
再乘 Osmosis：3 × 1.5 =  **4.5×**

**Pyramid 2× · Theme 2× · Osmosis 2×** 
先合并：2 + 2 − 2 + 1 = 3
再乘 Osmosis：3 × 2 =  **6×**

所有条形使用相同刻度：完整条长代表本图的 6 倍，不是平台上限。示例是假设计算，不是实测收入。

**它怎么影响 Base Payment？**

更高的适用倍数 → 提高 Quality Factor → 影响基础报酬。Base Payment 还有 Quantity、Self Growth、Value 三个组成部分；质量与数量因子还会相对于其他顾问缩放。

**因此：multiplier 提高，不是 daily payment 的简单相乘。** 不能把 3 倍质量加成直接理解为原来 10 美元就变成 30 美元。 [[来源]](/hc/en-us/articles/6314645381655)

## 03 | 优秀研究员的五步路线

不要从“全平台最高倍数在哪里”开始，而要从 **“分配给我的 Theme 是什么”** 开始。

**01 · 确认自己的 Theme**

查看分配通知、活动说明和公告，确认时间、区域/延迟、数据范围、Alpha 类型与资格。 **别人的 Theme 不一定适用于你。**

**02 · 在 Theme 内找高倍数字段**

优先研究 **有合理逻辑、覆盖可用、金字塔倍数较高** 的数据。字段是起点，最终要检查完整 Alpha 的模拟结果及活动匹配，不要只看单个字段页面的数字。

**03 · 先做出有效 Alpha**

先验证经济逻辑、缺失值、覆盖、换手、集中度与相关性，再完成提交检查。 **不要为高倍数硬塞字段，更不要为过测试加入噪声。** Multiplier 是加成，不是质量的替代品。

**04 · 再争取适用的 Python 加成**

若当期活动对合格 Python Alpha 有额外激励，核心信号成立后再开发 Python 实现或拓展，按活动规则确认新的倍数。 **不是“换个语法就自动加倍”** ，也不要假设所有账户都有固定 Python 奖励。

**05 · 认真分配 Osmosis**

从自己的池子选出逻辑清楚、成本后表现合理、相互补充的 Alpha。分散区域、数据与研究思路，避免给一批高度相似的表达式集中分配点数。 **已有足够的合格 Alpha，就不要让 Osmosis 长期空着。**

 **100k**

scope = 区域 × 延迟。可以选择不同类型、不同提交日期的 Alpha，不必只看最近提交。以上条件来自 [官方 Osmosis 指南](https://platform.worldquantbrain.com/learn/documentation/consultant-information/osmosis-allocation-guide-consultants) 。

**时间别弄错：** 每周日  **23:59 EST** 锁定配置，按指南延迟七天用于后续计算。今天调整，不代表今天的排名就变化。

**为什么要认真配，而不只是随便填？** 每日系数取决于组合表现。应观察成本后表现、相关性和共同回撤，逐步改进，而不是因短期波动频繁大改配置。

**有效 ≠ 保证 2 倍。** 不分配按本文口径 Osmosis Multiplier=1；有效配置的 Osmosis Multiplier 在 1–2 之间，不会拉低这一系数，Osmosis Multiplier>1 才产生额外提升。若双方 Osmosis Multiplier 都为 1，这一环节相同；也不能仅凭 Osmosis Multiplier 判断谁的实际 daily payment 更高。

## 05 | 今天就能检查的六件事

- **Theme：** 是分配给我的、且仍在有效期内的活动吗？
- **字段：** 活动范围内有没有更高倍数、逻辑也说得通的方向？
- **Alpha：** 质量、覆盖、成本、稳健性和提交检查过关了吗？
- **匹配：** 确认了完整 Alpha 的适用倍数，而不只是字段页面吗？
- **Python：** 若活动有额外激励，实现满足具体资格吗？
- **Osmosis：** scope、数量、点数正确，组合也认真筛选了吗？

**找到自己的 Theme → 选高倍数字段 → 做好 Alpha → 争取 Python 加成 → 认真配置 Osmosis**

不是只追求更多提交，而是把 **活动、数据、信号、实现和组合** 连成一个完整的研究流程。

从合并公式 sum − n + 1 可以直接推出一个帖子没点破的结论： **多个低倍数的叠加不如一个高倍数** 。比如三个 1.5 倍适用项：1.5+1.5+1.5−3+1=2.5；而两个 2 倍：2+2−2+1=3。n 是惩罚项，每多一个适用项就多减一次 1，所以"往多个低倍数活动里广撒网"在数学上就是吃亏的。研究排程上应该反过来： **集中火力在倍数最高、又真有经济逻辑可做的那个 Theme 上** ，而不是雨露均沾。

补一个从公式结构里可以直接读出来的决策规则，帮大家省点力气。合并公式 f = Σ(m_i) − n + 1 有个容易被忽略的性质：在已有 n 个倍数的组合上再增加一个倍数 m，合并倍数的增量恰好是 (m − 1)，而不是 m。也就是说，把一个 1.2 的 Theme 追进来，对合并倍数的贡献只有 0.2，几乎可以忽略；而一个 2 的 Theme 贡献是 1.0，是前者的五倍。所以选主题/字段时真正该比的不是倍数面值，而是 (m − 1)——低倍数主题的追逐性价比极低，时间该花在你能真正打到的最高倍数上。Osmosis 的杠杆又完全不同：它整体乘在合并倍数之后，1.8 意味着整个质量因子放大 80%，且对所有 scope 同时生效，这决定了资源分配顺序——先用 (m−1) 把合并倍数做厚，再把池子配到有效，因为同一份研究时间投入在 Osmosis 上的边际产出通常高于去凑一个低倍数主题。另外，倍数都会相对其他顾问缩放，所以这个乘数环节真正比的是相对位置，而不是绝对数字，锁定自己的最佳组合比追求单日最高系数更划算。
