### 评论 #1 (作者: ST74846, 时间: 2个月前)

- 必答一：
  Long Count 表示 Alpha 投资组合中最终交易权重大于 0 的股票数量，即被做多的股票数量；Short Count 表示最终交易权重小于 0 的股票数量，即被做空的股票数量。它们统计的是持仓股票数，而不是交易次数或历史累计买卖次数。
  在 BRAIN 中，Alpha 表达式首先为股票池内的每只股票产生一个信号值。平台再根据模拟设置，对信号进行 Delay、Decay、Neutralization、Truncation 和权重标准化等处理，得到每只股票最终的交易权重。某只股票的最终权重大于 0，就计入 Long Count；小于 0，就计入 Short Count；等于 0、数据为 NaN 或当日不在有效股票池中的股票，不计入两者。
  按日期 t 计算：
  Long Count(t) = 当日所有满足 weight(i,t) > 0 的股票数量；
  Short Count(t) = 当日所有满足 weight(i,t) < 0 的股票数量。
  平台年度回测表显示的 Long Count 和 Short Count，可以理解为该年度各交易日多头和空头持仓数量的平均值。
  例如，五只股票的原始 Alpha 值为 [1, 2, 3, 4, 5]。如果 Neutralization 设置为 Market，平台会先减去横截面均值 3，得到 [-2, -1, 0, 1, 2]，再将其标准化为交易权重。最终有两只股票权重为正、两只权重为负、一只权重为零，因此 Long Count = 2，Short Count = 2。
  这也说明，Long Count 和 Short Count 不能只根据原始数据的正负直接判断，而应根据 BRAIN 完成中性化等处理后的最终权重判断。

`anl4_cff_flag != 0 ? 1 : 0`

结果 Long Count 约为1949，说明平均每天约有1949只股票存在非零的有效标记。

随后改变  `ts_std_dev`  的时间窗口：

`ts_std_dev(anl4_cff_flag, 5) != 0 ? 1 : 0`

`ts_std_dev(anl4_cff_flag, 22) != 0 ? 1 : 0`

`ts_std_dev(anl4_cff_flag, 66) != 0 ? 1 : 0`

`ts_std_dev(anl4_cff_flag, 252) != 0 ? 1 : 0`

实测 Long Count 分别约为2、14、46和180，Short Count均为0。Short Count为0是因为条件表达式只输出1或0，不会产生负数。

观察窗口从5日扩大到252日后，Long Count虽然持续增加，但252日结果180仍远低于非零覆盖基准1949。说明绝大多数股票的该字段在一周、一个月或一个季度内不会改变；即使观察约一个交易年，也只有少部分股票的标记类别发生变化。

因此，我认为  `anl4_cff_flag`  属于低频、无固定周期、事件触发型数据，而不是固定的日更、周更、月更或季更数据。只有在分析师发布新的融资现金流预测、修改预测类型或发生其他预测事件时，它的类别才可能改变。

这里还需要区分“预测内容更新”和“flag类别更新”：分析师可能修改了预测金额，但如果前后仍然都属于 revision 类型， `anl4_cff_flag`  的值可能不变。因此本测试测到的是 forecast type 类别的变化频率，不一定等于分析师预测金额本身的更新频率。

现实生活中，它类似于员工档案中的“新入职、转岗、续签、离职”等状态标签。员工档案每天都存在，但正常上班不会使标签每天改变；只有发生入职、转岗、续签或离职事件时，状态类别才会更新。这与  `anl4_cff_flag`  只有在预测类型事件发生时才改变的特点相似。

### 评论 #4 (作者: ST74846, 时间: 2个月前)

必做3：

`ts_std_dev(x, d)`  的含义是：计算数据字段  `x`  在过去  `d`  个交易日内的滚动标准差。

标准差用于衡量一组数在窗口内是否发生变化：

- 如果过去  `d`  天的值一直相同，例如  `[3, 3, 3, 3, 3]` ，标准差为  `0` 。
- 如果窗口内至少有一次变化，例如  `[3, 3, 4, 4, 4]` ，标准差大于  `0` 。

因此，使用下面的条件表达式：

`ts_std_dev(x, d) != 0 ? 1 : 0`

可以把“过去  `d`  天内该数据字段是否更新过”转化为 1 或 0：

- 标准差不为 0，输出  `1` ：该股票在过去  `d`  天内发生过数据变化。
- 标准差等于 0，输出  `0` ：该股票在过去  `d`  天内没有发生数据变化。

然后在 Neutralization 设置为 None、Decay 为 0 的情况下进行回测。由于表达式只输出 0 或 1，Long Count 可以近似理解为：平均每天有多少只股票在过去  `d`  天内发生过一次或多次更新。

通过依次改变  `d` ，就可以判断更新频率：

- `d = 5` ：检查近一周是否更新；
- `d = 22` ：检查近一个月是否更新；
- `d = 66` ：检查近一个季度是否更新；
- `d = 252` ：检查近一个交易年是否更新。

如果一个字段是日更数据，例如收盘价，那么即使  `d = 5` ，大多数股票的  `ts_std_dev`  也不为 0；如果一个字段按季度更新，那么  `d = 66`  时的 Long Count 会明显接近该字段覆盖的股票数量，而在  `d = 5`  或  `d = 22`  时会低得多。

本次  `anl4_cff_flag`  的测试中，窗口从 5、22、66 到 252 天时，Long Count 约为 2、14、46、180，说明窗口越长，检测到变化的股票越多；但即使一年窗口也远低于非零覆盖股票数。因此它不是固定日更、周更、月更或季更，而是低频、事件触发型更新。

需要注意： `ts_std_dev(x,d)`  只能识别字段“数值或类别是否变化”，不能识别“数据被重新发布但数值仍相同”的情况。对于  `anl4_cff_flag` ，它测到的是预测类型从 new、revision 等类别之间的变化频率，而不一定等于分析师预测金额本身的更新频率。

### 评论 #5 (作者: ZZ38216, 时间: 2个月前)

**必做1：** Long Count（多头计数） 在某一交易日， Alpha 信号值为正值，被分配了正权重（即建议买入/做多）的股票数量。 Short Count（空头计数） 在某一交易日，Alpha 信号值为负值，被分配了负权重（即建议卖出/做空）的股票数量。

假设股票池只有 5 只股票，它们的收盘价（close）分别为 [5, 15, 66, 85, 25]，Alpha 表达式为 -close（取收盘价的相反数）。

第一步：原始 Alpha 值

原始信号为：[-5, -15, -66, -85, -25]。

第二步：Market 中性化处理

计算平均值：(-5 + -15 + -66 + -85 + -25) / 5 = -39.2

原始值减去均值，得到：[34.2, 24.2, -26.8, -45.8, 14.2]

第三步：归一化处理

计算正数总和：34.2 + 24.2 + 14.2 = 72.6

计算负数绝对值总和：26.8 + 45.8 = 72.6

为让正数部分总和为 0.5，负数部分总和为 -0.5，缩放系数为 0.5 / 72.6 ≈ 0.006887。

最终权重约为：[0.2355, 0.1667, -0.1846, -0.3154, 0.0978]

第四步：统计计数

Long Count = 3（第 1、2、5 只股票的权重大于 0）

Short Count = 2（第 3、4 只股票的权重小于 0）

结论：该 Alpha 策略在当天会做多 3 只股票（第 1、2、5 只），做空 2 只股票（第 3、4 只）。

**必做2：** Cash Flow From Financing Activities - forecast type (revision/new/...)
融资活动产生的现金流——预测类型（修订版/新版本等）

通过秒速判断为融资活动产生，那么一家公司不可能短时间内一直会有融资活动产生的现金流，从上述回测截图显示，判断这个是事件驱动，在一年期的时间窗口内有较多的long count变化，对于 anl4_cff_flag 的预判：N=252 可能略高于 N=126，主要贡献来自年底分析师集中上调/下调全年预测。我认为上市公司季度业绩预告/财报发布跟它的更新频率类似，因为：N=252代表了全年的累积，N=66出现了较多公司的交易更新，n=126 相当于半年度的累积，依此推断为季度更新。

周期刚性：两者都绑定在固定财务周期（季度），不会随机发生；

时间窗口集中：财报发布集中在 1月/4月/7月/10月 的特定几周，与 anl4_cff_flag 的修订事件集中爆发一致；

稀疏性：对单只股票而言，一年只有 4 次更新机会，大部分时间处于"静默期"（值为 0），与该字段日均 Long Count 仅个位数一致；

事件驱动：只有当外部信息（财报）触发时，内部状态（预测值）才改变，与 ts_std_dev 检测到的"窗口内变化"逻辑相同。

### 评论 #9 (作者: Liangwen Deng(JD11282), 时间: 2个月前)

课后作业3:

**任何一组数据，只要内部存在哪怕一个不同的数值，其标准差必然大于 0；反之，只有当所有数值完全相同时，标准差才等于 0。**   `ts_std_dev`  充当了一个极其灵敏的“变化探头”，只要在 d 天内发生过任何数值变动，它都会立刻捕捉到。

`ts_std_dev(x, d) != 0`  测频率的逻辑是： **不断把窗口 d 缩短，只要缩短后“有变化的股票数”没有急剧减少，就说明该字段的变化周期比这个窗口还要短。**  你的数据在 d=5 时依然饱和，所以它是日频。

### 评论 #18 (作者: YH18420, 时间: 2个月前)

必做3： `ts_std_dev(x,d)` 表示对每只股票分别计算数据字段  `x`  在最近  `d`  个交易日内的时间序列标准差。标准差用于衡量窗口内的数据是否存在波动：如果最近  `d`  天的字段值完全相同，则标准差为0，说明该字段在这个窗口内没有发生取值变化；如果窗口内至少出现两个不同的有效值，则标准差大于0，说明该字段在最近  `d`  天内至少发生过一次变化。

为了便于统计，可以使用：

```
ts_std_dev(x,d)!=0?1:0
```

当标准差不为0时返回1，表示字段在过去  `d`  天内发生过变化；标准差为0时返回0，表示字段值保持不变。在 Neutralization 设为 None、Decay设为0的情况下，返回1的股票通常会计入 Long Count，因此 Long Count可以近似表示平均每天有多少只股票在最近  `d`  天内发生过字段取值变化。

通过改变  `d` ，可以比较不同时间尺度下发生变化的股票数量。例如， `d=5` 约对应一周， `d=22` 约对应一个月， `d=66` 约对应一个季度， `d=126` 约对应半年。如果较短窗口的 Long Count已经很高，说明字段更新较频繁；如果短窗口很低，而66日或126日窗口明显提高，说明字段变化较低频，可能呈季度性或事件驱动特征。

需要注意， `ts_std_dev(x,d)` 只能判断过去  `d`  天内是否发生过至少一次取值变化，不能计算具体更新次数或准确更新日期。此外，如果数据虽然更新但新值与旧值相同，标准差仍然为0；如果窗口内有效数据不足，结果还可能为NaN。因此，该方法测量的是字段数值的变化频率，是对数据更新频率的近似判断，而不是对数据库真实更新时间的精确统计。

在BRAIN平台中，long-count和short-count指的是在回测的某一天，投资组合中 **净权重为正（做多）** 和 **净权重为负（做空）** 的股票数量。

 **`short-count`** : 统计投资组合中， **权重值 < 0**  的股票个数。

#### 步骤1：评估表达式，生成原始Alpha向量

#### 步骤2：中性化（减去均值）

计算步骤1中8个向量值的平均值（假设为0.5），然后从每个值中减去它。新向量的总和为0，正值和负值相抵消。这一步的结果是 **初步的、未缩放的投资组合权重** 。

#### 步骤3：归一化（缩放权重）

将上一步的向量值，除以所有值 **绝对值之和** 。在这个例子中，绝对值之和是  `0.389 + 0.278 + ... + 0.388 = 2.3` 。缩放后， **所有权重的绝对值之和为1** 。

这是最终的权重向量，也是分配资金的基础。

#### 步骤4：构建投资组合，并统计 long-count 和 short-count

这是最关键的一步。我们根据 **步骤3生成的归一化权重（G列）**  来分配资金，并同时统计 `long-count` 和 `short-count` 。 **统计依据非常简单：直接看权重的正负号。**

- **对于权重为正的股票（例如股票5至股票8），系统会建立多头头寸** 。这些股票的数量，就是  `long-count` 。

### 什么样的数据更新频率跟这个类似

我认为体检世界杯比赛的输赢预测信息（无论进球数）跟它的更新频率类似，因为时间长，另外只有输、赢、平三个可选项。

## 必做3：解释 `ts_std_dev(x, d)` operator 能测出数据更新频率的逻辑

`ts_std_dev(x, d)` 逻辑是计算股票 d 天内标准差。

`ts_std_dev(x, d) != 0 ? 1 : 0` 因子有：

如果 d 天内数据保持一致，则最终结果是 0；如果 d 天内数据发生更新，则结果是 1。

这个探测因子假定了在两次变更之间，数据不发生变化且都有值。按照平台 NaN Handling 原则，如果 Off，则 d 天内数据有 NaN，最终结果也是 NaN。

在完美的情况下，发生数据更新之后的 n-1 天内数据都是 > 0，则通过 Long Count 可以对此进行计数。所以相当于对数据进行根据时间分组。

每个股票的 Long Count 计数为：

```text

min(((d - 1) * 252 / 更新间隔天数), 252)

```

因子的输出 Long Count 为：

```text

min(((d - 1) * 252 / 更新间隔天数), 252) * 股票数量 / 252

```

假设更新频率为季度，更新间隔天数 = 66：

```text

Long Count = (65 / 66) * 股票数量

```

此时，用 d = 22 计算：

```text

Long Count = (21 / 66) * 股票数量

```

大概是 1/3。

用 d = 252 计算：

```text

Long Count = (252 / 252) * 股票数量

```

趋近真实股票数量。

所以：通过 `ts_std_dev(x, d)`，d 不断从小到大增加，得到最终的使 Long Count 趋近股票数量的 d。

这里也说明了一个点：那六个方法必须要得到一个前置条件——这些探测的因子需要知道 raw data，即原始值是不是 0、是不是 NaN。这关系到如何处理 NaN，使得最后的更新频率是一个正确的数据。如果数据本来就是 0，再将 NaN 处理成 0，会丢失更新次数。

必做3：

ts_std_dev(x, d) 运算函数返回输入序列 x 在过去 d 天的标准差。标准差是量化数据集中变异或离散程度的关键统计量。在时间序列的背景下，了解某个变量（如收益率或价格）在指定窗口内的波动程度或稳定程度。

低标准差意味着值接近均值，而高标准差则表明值分布更分散。

关键在于把定义推到极端：标准差等于 0 当且仅当窗口内所有值完全相同（每个平方偏差都是 0）。比如 x = [0.01, 0.01, 0.01, 0.01, 0.01] 时 ts_std_dev = 0，而官方示例 [0.01, 0.02, -0.01, 0.00, 0.03] 因为值在变化，得到约 0.0141。所以“窗口内 std 是否大于 0”恰好等价于“窗口内是否出现过不同的值”。

估计类数据在没新数据的日子会被回填（用最近的旧值填充），两次真实更新之间序列是常数，std = 0；真实更新到来时值发生变化，std > 0。因此 ts_std_dev(x, d) != 0 ? 1 : 0 就是“过去 d 天内是否更新过”的 0/1 指示器，回测后的 Long Count 就是日均“d 天内更新过”的股票数。

再用不同窗口长度扫描：更新周期为 T 的字段，d 天窗口撞上更新的比例约等于 min(1, d/T)，所以哪个窗口的比例跳到接近 100%，更新周期就是哪一档（5=周、22=月、66=季）；如果都远小于 100%，就说明字段更新极稀疏，用比例可以反解出真实周期。

### 评论 #38 (作者: YM65725, 时间: 20天前)

**问题 3**

`ts_std_dev(x, d)`  的含义是：计算数据字段  `x`  在过去  `d`  个交易日内的标准差。如果过去 d 个交易日，该股票发生过变化，则标准差不为 0，输出 1；反之该股票没有发生过变化，输出 0。

下面的 Alpha 表达式

```
ts_std_dev(x, d) != 0 ? 1 : 0
```

可以把“过去  `d`  天内该数据字段是否更新过”转化为 1 或 0。

假设一个数据字段是季度更新，一年约 66 个交易日才更新一次。在更新日，该股票有数据；更新日之后，数据变成 NaN，直到下一季度更新，所以一支股票在任意一天有数据的概率是 1/66。如果取过去 N 天窗口，窗口内有数据的概率约为 N/66，因此 \mathrm{Long}+\mathrm{Short}\approx \mathrm{coverage} \times (N/66)。当 N = 66 时，Long + Short 接近实际覆盖率；当 N = 22 时，Long + Short 约为覆盖率的 1/3；当 N = 5，更低。
