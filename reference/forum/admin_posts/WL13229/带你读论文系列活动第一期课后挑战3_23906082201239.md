*****问题一：

在参加2024 BRAIN量化训练营第二期学习时，Day4作业的必做2要求对一个Alpha idea进行表达并尝试改进，当时我选择了一个关于earning的比率，该idea是来自于平台提供的example。基于此，我构建了初始的Alpha指标：`retained_earnings / sharesout`，改进思路是考虑公司的纵向自我提升考量﹑横向行业比较，结合按照季报发行的频率，形成改进版Alpha表达式为：

```
rank(ts_delta(retained_earnings / sharesout, 63))
```

尽管Alpha的质量从Need to improve改善为Average，但始终未能通过IS testing。

当时老师给我comment：“若是能找到合适的分组进行group比较，相信Alpha会有进一步的提升。”

其后进行了一些尝试，但Alpha的表现未能改善至可以通过IS testing。

现在复盘，当时有几个地方未能考虑：

（1）settings没有依据地进行调整，企图纯粹为了通过IS testing；

（2）在datafield和operator的掌握和理解上仍非常不足，所以并没有有效利用数据特征，并选取相对合适的operator；

（3）即使侥幸通过IS tesing，很有可能也会存在潜在overfitting的问题，在稳健性测试及分析上的依据不足。

*****问题二：

在《带你读论文》系列活动第一期课后挑战1，正好读到一篇论文里面是有提到：EP Earnings-to-price ratio，Sign是与returns呈正相关。所以，当时构建一个Alpha：

```
EP= if_else(mdl175_retainedearnings > 0, mdl175_retainedearnings/cap, nan);ABNTURN=-(ts_mean(volume / sharesout, 20) / ts_mean(volume / sharesout, 250));alpha=rank(EP)+ABNTURN;group_neutralize(alpha ,bucket(rank(cap),range='0.2,1,0.2'))
```

尽管当时在构建Alpha上有了一定理论依据的支撑，但仍未使得IS tesing和Correlation通过。当时老师在课堂上简单点评说可以考虑如何换datafield把Correlation降下来。

鉴于此，在本次作业的中，尝试能够借助对论文的研究和实现，并尝试更合适的datafield和operators去解决上述问题。

**文章基础数据字段（datafield)：**

1.根据文章对earnings ratio的定义，实质上突出显示那些高盈利但市值较低的股票。我通过搜索earnings，在非常多个dataset均有涉及相应的datafield，例如Analyst Estimate Data for Equity中anl4﹑Company Fundamental Data for Equity中的fnd6等，也包括estimate﹑ttm﹑基于财报本身的等多种形式的表达。

此外，对于earnings的理解，文章提到是某种形式的netincome，但当然如果后续进一步延申retainning earnins或其他的profit。而市值的形式也非常多，例如可以直接是cap，或者某种价格和流通量的乘积等。这些都为泛化之Available Datafield带来很多可能性。

2.基于文章对市值的代理变量定义为价格*流通量，所以选择了close和sharesout。进一步探索这两个datafields，coverage都是100%，且都是daily更新。

**Robustness Check：**

1. 一个数据集中的产出效率如何？
2. 参数敏感性如何？
3. IS/OS ratio-average and std？

这三个问题，一并回答：

第一类：在同一个数据集中如果id是相同的话，产出效率还是不错的，例如尝试了anl4相同含含义的但不同具体形式的datafiled，也都能通过IS testing，敏感性差不多，并且IS/OS 的表现也差不多。

第二类：如果是使用延申含义的，例如本文的例子，研究文章中指出是netprofit，如果延伸为retainning_earnings，可能有一两项不能通过，如果进一步作出调整，也有部分可以通过，但对参数的敏感性就完全不同于第一类，IS/OS 的表现会与第一类相差比较大，且自身的IS/OS的表现也相差较大。

第三类：如果是替换的话，例如文章中的市值表现，从价格*流通量改为直接是使用cap，就需要把cap的数据特点，尤其是更新频率考虑进去，如果充分考虑了这一特性，也是可以通过，并且在敏感性和IS/OS表现与第一类相似。

所以，总体而言，就本文的例子而言，只要datafield是严格遵守文章原意的表述，例如文章表述是netprofit和cap，就使用或间接（通过计算表现）的netprofit和cap的datafield，都比较容易通过，且表现差别不大。但如果使用的是延伸意思或者扩展到更广义的理解，表现相差非常大。可能主要是跟不同dataset下或不同含义的datafield的特征有关，由此可能也需要变换对operator的变化。

### 参数敏感性

- 对新闻数据的敏感性：对于其他新闻数据的理解不足，统计特征不了解，统一进行 rank 和求和操作可能不恰当
- 对时间序列的敏感性：基于对新闻数据的操作，不同时间算符算出来的变量纲好像不对
- Classification Group 敏感性：只能在 market、sector、industry，细分就不行了。估计是到了行业内部，行业的 beta 会对这个信号产生比较大的影响，如果针对行业进行风控应该能重新提高表现
- Risk Group 敏感性：在我能查到的分组中，表现都不是很好。
- 对反常拉锯强度的敏感性：季度和半年这种信号更重要，和论文中说的月度的信号不一样。

### IS/OS

## 反思与思考 ：

其实优化和泛化的界限没有那么明显，老师 Lecture 2 上课讲授优化时候，也有把 rank 换成 normalize，我在研究的时候也发现做一些简单的“泛化”有助于帮助我确定，新加入一个信号/代码是不是真的不起作用（至少心理上能够起到一些作用）。

IS/OS 需要提交以后，但是泛化操作大概率不会从根本上改变因子，也就是和第一个提交的因子相关性很高，大概率是过不了的，所以也就没法比较 IS/OS 了。而比较 Train/Test，作为 User 选择两年 test，在我的信号里面正好把一个两段“不同斜率”的 PnL 曲线切开了，Train 的时候调参其实也挺容易 Overfitting 的。

作为 User 没有 API，没有计算机帮助能做的泛化挺有限的，我每一个泛化角度都是从原始表达式出发进行改变的，多个泛化角度的交叉效果如何就未知了；另外自己从网页整理表格也是一个不利于挑选 Alpha 的缺憾，不太利于把精力集中在寻找 alpha 上。

### 评论 #16 (作者: LP57781, 时间: 2年前)

文章名称：《Good Volatility, Bad Volatility, and the Cross Section of Stock Returns》
文章链接： [https://public.econ.duke.edu/~boller/Papers/JFQA_2020.pdf](https://public.econ.duke.edu/~boller/Papers/JFQA_2020.pdf)

文章idea：文章考虑到资产回报的波动性自然可以分为与正负价格变动相关的“好”和“坏”波动，由此，文章使用半方差度量方法，即将总方差分解为与正负高频回报相关的独立部分，并将两个半方差度量的相对差值，作为衡量个别股票“好”与“坏”波动性的变量。进一步基于股票的“好”与“坏”波动性的相对差值（即“好”减去“坏”波动性）对股票进行排序，从而达到预测未来收益的横截面变化。研究结果显示，基于“好”减去“坏”波动性的组合投资策略，在经济角度和统计角度都有显著变作用，且这种相对差异能显著预测未来收益。该项研究可能反映了投资者对大的突然价格下跌或负面“跳跃”的过度反应，或限制套利的行为偏见，为理解股票市场中波动性与收益之间的关系提供了新的视角。
