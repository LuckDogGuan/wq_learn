# WorldQuant Brain Core

Core 是通用机制层。认证、请求、分页、时间切片、重试、缓存和检查点在这里复用；
RA/PPA 的筛选门槛、标签、流程顺序与报告格式留在业务目录。
旧业务便利接口保留兼容，不作为新接口设计模板。

## 本轮变更与入口

- 时间窗口拉取：`Core.api.fetch_alpha_window`，返回记录、完整性状态、失败范围、请求数。
- 普通排序分页：`Core.api.pagination.iter_alpha_pages`，供候选排名和 OS 增量刷新复用。
- 显式目录同步：`Core.catalog_sync.sync_catalog`；`CatalogDB.fetch_all_scopes` 仅为旧接口适配。
- 人工提交入口：`提交因子/submit_alphas.py`，只负责 ID 配置和手动启动。
  通用检查等待、提交与核验统一在 `Core/api/submission.py`，不包含 RA/PPA 门槛。
- 研究排序策略：`sim/research_policy.py`。爬山流程显式注入；通用候选管理默认不计算硬门槛通过数。
- 公共入口只暴露多模拟；任务池和 API 均校验每批 2–8 条，不发起单条尾批。
- `machine_lib.py` 使用显式导出；新增调用优先直接导入所需模块。

## 拉取契约

`start/end` 必须带时区，采用 `[start, end)`。按日期传参的旧 API 使用北京时间，
结束日转换为次日零点。窗口拉取保留微秒，支持月末和时区边界。

每页最多 100 条；窗口总数超过默认 500 时二分时间窗，不是直接跳过剩余记录。
这些值是可配置的平台适配策略，不是 RA 门槛。相同时间戳过密且无法继续分窗时返回
`PARTIAL`，不声称取全。平台不存在快照隔离，因此完成状态也不是对未来数据不变的保证。

| 状态 | 含义 |
| --- | --- |
| COMPLETE | 当前查询所有窗口完整观测；允许结果为零 |
| PARTIAL | 已有记录，但部分页/窗口未完整观测 |
| PENDING | 未取得可靠记录或响应不可观测 |

缺少 `results/count`、非法 JSON、截断页、重复分页或请求失败不会当成空结果。
检查点按范围、查询条件、分页和切片参数隔离；变更条件或损坏检查点会安全重读。
一个检查点由一个运行进程持有，不支持多个进程并发写同一文件。

详细接口、迁移风险与操作符来源见 [当前契约](doc/13_review_contract.md)。

## 缓存与兼容

- `runtime_data/catalog.db` 与 `runtime_data/sc_ppa/` 保持原路径，不删除历史数据。
- RA 保留历史记录；旧未完成分页可能安全重取。失败不推进水位，查询条件改变会失效旧水位。
- PPA 的旧日 JSON 不修改。新检查点位于原缓存目录的 `beijing_v2/`；
  旧日文件缺少范围和完整性证明，首次迁移需要重新读取平台，随后复用新检查点。
  当前日重新查询，历史日复用已完成结果；本地筛选不修改旧缓存。
- Validator 不再隐式下载参考池；缓存缺失明确返回不可观测状态。
- 数据库连接在上下文退出时关闭，不再持续占用 Windows 文件。
- 人工诊断位于 `tools/manual/`，维护脚本位于 `tools/maintenance/`。
  原脚本保留兼容入口；导入不联网、不清库。执行数据库清理仍需明确确认。
- 损坏的 `factor/filter/alpha_evaluator.py` 已修复；
  原始字节保存在同目录 `alpha_evaluator.py.encoding-backup`。

## 手工提交修复

在“提交因子”目录执行：

```powershell
python .\submit_alphas.py 3q936AEN
```

填写 ALPHA_IDS 后手动运行即为本次授权，不再输入二次确认文本；脚本先读取当前提交状态，再检查 Alpha。
HTTP 200、空正文且带 `Retry-After` 表示计算尚未完成，应继续只读查询，
不能直接解释成“没有检查项”。默认最多 30 次、120 秒等待预算，并传递给请求重试层。

只有检查明确通过才发送一次逻辑提交请求；传输错误、429、5xx 不盲重发提交。
两秒后按 ID 只读核验一次。超时保持 PENDING，不证明提交失败，也不证明成功。
实际提交必须由用户亲自运行；定时入口没有本次人工确认会被阻止。
