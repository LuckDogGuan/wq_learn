本文件修正 `spc/SPC_SUBMISSIONS_API_REFERENCE.md` 中与本次实时响应不符的内容。原说明保留，不作为当前模型可用性的证据。

## 已核验接口

| 接口 | 本次响应 | 使用方式 |
| --- | --- | --- |
| GET `/competitions/spc/submissions` | 200，`count/next/previous/results`，列表包含完整 prompt、sampleOutput、模型、版本、weight、status | 读取全部分页；用列表的实际 status 记录平台稳定状态 |
| GET `/competitions/spc/submissions/{id}` | 200，但结构是 `count/next/previous/results`，每项为 `date/weight` | 这是权重日期记录，不能当成生成状态详情 |
| OPTIONS `/competitions/spc/submissions` | 200，POST 字段约束和模型族 choices | `modelVersion` 是自由字符串，未提供合法版本枚举 |
| OPTIONS `/competitions/spc/submissions/{id}` | Allow=`GET, PUT, PATCH, HEAD, OPTIONS` | 未声明 DELETE，不执行实体删除 |
| DELETE `/competitions/spc/submissions/BA190dB` | 405，`Method "DELETE" not allowed.` | 用户再次明确要求实体删除后，针对一条已失败且清零的对象实测；平台不支持该操作 |
| GET `/competitions/spc`、`/competitions/spc/models` | 404 | 不能作为模型目录 |

请求 `limit=200` 实际第一页返回 100 项并提供 next；必须继续分页。本次初始列表共 136 条、50 个策略名称，48 条权重非零。其中 15 条 `Active`，25 条 `Unstable Output`，8 条 `Failed`。

初始 136 条 sampleOutput 均有 2 个对象，提示词却要求恰好 10 个。2 个样例对象的 JSON 格式、七个字段、数值边界、ISIN 校验位及 MIC 形式通过本地校验；这不证明股票当日可交易、预测有效或者交易所映射准确。

## 处置标准

- 明确 Failed/Unstable Output 且 weight 非零：逐条 PATCH weight=0.00，并重新读取全量列表确认。保留原内容和旧权重，方便回溯。
- 旧对象无法原地改 prompt；替换对象初始 weight=0.00。先观察平台状态，再决定是否激活。旧稳定对象在新对象确认稳定前保留。
- 用户随后明确要求稳定项不变：原有 101 条稳定对象全部保护，包括 15 条权重非零与 86 条权重为零的历史稳定对象；后续仅替换原来的 35 条 Failed/Unstable Output，稳定对象即使有样例数量警告也只记录，不改配置。
- `Active` 按 OPTIONS 的说明解释为平台评价的 `Active: Stable Output`；这是平台状态证据。平台没有公开实际生成文本、多次独立运行输出或底层供应商模型 ID。
- 平台接受自由 modelVersion 字符串，不足以证明底层路由；不把简单 POST 成功表述为模型实际调用已经确认。
- 没有枚举的版本，仅在官方存在且本次 SPC 接受、状态稳定后列为可用 SPC 配置；底层路由仍标记未公开。
- 网络错误或响应不完整记录 PENDING，先只读对账，不重复 POST。日新增限额耗尽立即停止新增。
