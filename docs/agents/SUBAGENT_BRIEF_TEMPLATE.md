# 子代理简报模板（DSH flash · 闭环）

规则来源：ADR-0001。一个子代理对一个任务负责完整闭环：**提出意见 → 修改 → 结果**。不要把同一流程拆给其他代理。每个子代理最多 4 轮对话，用满即丢弃；任务包按定时巡检间隔的 1.5 倍设计（3h → 约 4.5h 工作量，超 2h 的拆成带检查点的段）。启用前先 `dsh_worker_probe`。

把下面整段（填好 `<...>`）作为 `task`；子代理没有任何对话上下文。

```text
【任务】<一句话目标>
【工作区】c:\Wq\WorldQuant Brain （只在此目录内工作）
【必读】<绝对路径列表，如 .scratch/.../issues/NN-xxx.md、相关源码与配置>

【闭环（必须在同一次执行内全部完成并回报）】
1. 意见：先读上述文件，写出你的诊断与方案（不超过 15 行），说明改哪些文件、为什么、有哪些风险与替代做法。
2. 修改：按方案修改；只动【允许修改】里的文件。
3. 结果：运行【验收命令】；贴出真实输出的关键行；写明哪些验证你没做（不得假装通过）。
4. 回报：<=30 行，结构为「意见 / 改了什么(文件+要点) / 验收结果 / 未验证项 / 建议的下一步」。

【允许修改】<绝对路径列表>
【禁止】不 commit、不 push、不回测、不调用任何平台写接口或 /submit、不读 Password/config.yaml、
        不改 legacy_core/Core/runtime_data/ 与 reference/、不改 COMPLETED_FULL 台账行、不使用 + * add multiply trade_when、保持 Delay=1。
【验收命令】<如 python -m pytest tests/unit/test_xxx.py -q>
【进度与检查点】若预计超过 2 小时：每完成一段把进度写入 <绝对路径>/progress.md，再继续；任务包容量按定时间隔 1.5 倍备足。
【证据标记】结论一律标 [V]已验证/[R]有报告未复核/[C]条件成立/[U]未验证，并写适用坐标。
```

主 Agent 在收到回报后：用 `git status`/`git diff` 与验收命令复核 → 写有效/无效归因 → 更新 TODO 与工单状态。回报不等于证据。
