# 26 | 2025 年 10 月 23 日 AIAC 说明会

> 用 AI 从种子 Alpha 派生候选时，怎样区分经验证的改进和恰好取得高分的变体？

## 术语速查

| 术语 | 本课用法 |
|---|---|
| Parent Alpha | 为一组变体提供研究基准的种子 |
| Child Alpha | 继承种子假设并修改一个或数个设计点的候选 |
| Super Alpha | 在单腿验证后研究信号组合及其表现 |
| 测试期 | 用来观察未参加本轮选择的数据表现 |
| Notebook | 保存变体、结果和下一轮反馈，让过程可以复核 |

## 课堂走读

1. 先诊断种子。讲师让模型读父代的字段、表达式、已有设置和结果，并给出机制及弱点。发给模型前去掉账号信息，至少保留种子 ID、逻辑、地区、Universe、Delay、Neutralization、窗口和测试区间。重点找一项能够验证的问题。
2. 候选从一个改动开始。课程演示让 AI 提案并模拟。先获得解释，再检查字段和算子；同一批保持其它条件一致。例如课堂复盘比较了时间序列排序与标准化，也观察到窗口从 20 扩到 60 后表现可能变差。这些发现只描述此种子与所用数据。
3. 建本地父子映射。模拟前保存候选表达式、父代和设置，模拟后绑定结果 ID 并收集图表或指标。失败运行记录失败原因和可见状态。课堂通过标签和名称找回批次，本地练习先使用记录表，平台标签以授权为准。



4. 把结果喂回下一轮。每个候选记录「改了什么、实际发生什么、下一轮是否保留」。课上建议设置退出条件，例如果断收尾、修改方向或继续查找数据。研究里可以先设少量对照和时间预算，再依据可见证据决定后续。
5. 组合阶段回到测试期。逐个查看子代与组合完整测试区间，比较组合增量、相关性和回撤。单个子代的训练期表现不能代替组合验证。循环中每次能得到多少合格候选没有固定保证。

## 复现时的批次表

| 分组 | 唯一研究变化 | 固定或追加核对 |
|---|---|---|
| 父代基线 | 保持已知表达式 | 同地区、Universe、D1、测试区间和中性化 |
| 变体 A | 只修改一种时间序列变换 | 看覆盖、分期 Sharpe、换手、最大权重与相关性 |
| 变体 B | 保留变换，只改窗口 | 看差异是否跨区间持续，保留变差的数据 |
| 组合对照 | 组合使用已验证分支 | 和单腿在相同区间比较，检查组合相关性与回撤 |

实施前核对当前项目的禁用算子、D1 与人工提交规则。模拟遇 429、5xx、超时或缺子 ID 时仅留指纹并标为 `PENDING_RECONCILE`，冷却后只读对账一次，仍无结果则记录 `RESULTS_UNOBSERVED`。
