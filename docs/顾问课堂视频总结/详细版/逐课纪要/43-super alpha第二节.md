# 43｜Super Alpha 第二节：Combo 与 Reduce

课程把底层 Alpha 的日度 PnL、成交额和多空数量作为时间序列来理解，先定 Selection 候选池，再为 Combo 设计权重，并用 Reduce 解释输入形状变化。

## 先确定候选，再设计权重

**课堂演示**　课堂先讨论多个 Alpha 都通过条件时如何排队，再用常量 Selection 做全选基线，实际仍受权限和数量限制。保持候选集合一致时，可以单独测 Combo 对组合结果的作用。

| 概念 | 课堂含义 | 复现要核对 |
| --- | --- | --- |
| Selection | 决定候选池成员和可入池范围 | 权限、实际入池 ID、排序和限额 |
| Combo | 决定底层 Alpha 在组合中的权重 | 计算窗口、输入量纲和缺失处理 |
| PnL 与交易属性 | 可作为观察底层 Alpha 的日度数据 | 是否是当时可获取的序列、口径是否一致 |

## 一次可回滚的 Combo 对照

**复习练习**　把每个候选的时间序列作为一列，用同一批候选和同一 D1 配置建立一个简单权重基线。提出一个可检验的权重变化，例如根据过去的波动调整候选相对权重。测试时留好日期，确保用到的数据在对应时点已经可获得。

1. 固定候选，统一各序列频率和日期，检查缺失、低波动值及不同量纲。
2. 标明输入的各个维度。示意中，某个张量包含日期、底层 Alpha 和多个特征，按特征维聚合后仍保留「日期 × 底层 Alpha」。实际轴顺序以接口返回为准。
3. 保持 Selection 与 Settings 一致，分别跑基线和有明确假设的 Combo。观察累计 PnL、分段 Sharpe、Turnover、权重集中度和所选候选的实际数量。
4. 如果某几条权重长期过大，检查分母、缺失处理以及历史极端日。若有效成员很少，查筛选是否过严再解释组合表现。



**本项目约束**　D1 设置固定。候选集、权重口径和评估区间都作为实验记录留存。课堂说的可选数量属于当时权限和工具配置。
