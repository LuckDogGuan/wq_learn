# 28 | 2025 年 11 月 8 日 WorldQuant 会议下午场第三段

> 怎样把几天的账号进展、候选与平台信息写成可重跑、第二天还能核对的研究日报？

## 输入与输出

| 材料 | 使用方法 |
|---|---|
| 日期锚点 | 保存报告日期、时区、查询时点和窗口边界 |
| 账号与候选池 | 汇总当时能够读取的进展与候选状态 |
| 公告与地区动态 | 记公告发布日期、来源及可能影响 |
| 下一步实验 | 记录想验证的问题、现有对照、优先级和停止条件 |



## 课堂走读

1. **手工走通一次。** 明确当日日期，按课堂例子读取过去五天的 Alpha 情况，再查看活动、公告及新地区。把每类输入的查询时点和可读范围记在旁边，便于重跑。公开信息和私人结果分别标明来源。
2. **基于事实写判断。** 昨日结果放结果表，候选写清其当前状态。公告中提到新地区时，先记录其发布时间与适用范围，再把「核对该地区的 D1 字段覆盖」写为待办。读不到某类信息时写「暂未观测」，保留查询时点。
3. **固化步骤并新开会话复演。** 课程建议把完成过的操作整理为顺序明确的工作流，再在新会话用相同日期与输入执行，对照来源、条目数和建议是否能回到原始证据。先复核这份报告，再尝试别的工作流。



## 日报的最小记录示例

| 条目 | 示例填法 | 次日对照 |
|---|---|---|
| 已观测结果 | D1 候选 A 在指定区间有完整结果，链接本地记录 | 确认测试区间、指标和来源一致 |
| 待回收结果 | 某一批次只返回部分子 ID，保存任务指纹 | 冷却后仅做一次只读对账，仍无结果记 `RESULTS_UNOBSERVED` |
| 公开信息 | 公告提到某地区有活动，来源为公告及发布时间 | 核对活动开放范围、日期与研究条件 |
| 拟验证 | 固定 D1、股票池和区间，对比基线与一个有解释的参数变化 | 用实际覆盖、Sharpe、换手和分期结果判断后续 |
