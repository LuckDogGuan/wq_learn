# 33｜AI 工具、Community Leader Web App 与 AIAC 2.0 辅导

课程从 AI 打工人的候选生成讲到文件导入、批量回测、断点恢复以及赛事 Notebook。大量答疑涉及反馈滞后、向量数据和并发失败，适合边看课堂边核对自己的记录。

## 从想法到可解释的候选

**课堂演示**　现场使用找灵感、历史模板增强、对话优化和“72 变”等入口。工具接受的输入和输出各不相同。开始前先确定想补足的组合缺口，例如降低某类候选的换手，或寻找一种信息来源有区别的信号。

**复习练习**　用同一 Dataset 选两个输出。为每条写下数据字段、信号假设、算子选择及生成入口。用相同 D1 Settings 做小批对照，比较累积收益走势、Turnover、分段稳定性和同类候选重复程度。向量字段先核对是否要用向量统计得到合适的输入。顺序扫描太多相似表达式时，先缩小候选集并保留变化原因。

## 文件导入与断点恢复

课堂示范将表达式导出为带 Settings 的 JSON，再交给回测器。部分演示会先打乱候选顺序，要求续跑时使用当时那份文件以及一致的索引。



| 阶段 | 保留内容 | 观察和处理 |
| --- | --- | --- |
| 导出 | 文件命名、原始顺序、设置和候选数量 | 同一版本保留同一份候选清单 |
| 发起回测 | 各条请求指纹、批次与返回 ID | 区分发起成功、实际可见和完成结果 |
| 续跑 | 已完成 ID、未观测项和对应文件下标 | 沿用原始顺序，按已核实的状态推进 |

**本项目约束**　遇 429、5xx、超时或缺子 ID，存指纹并按只读对账流程处理。重新打乱清单会改变下标，在采用同一批次续跑前先核对入口文件。课堂展示的并发槽位和故障措施随工具版本变化。

## 赛事材料与质量选择

**课堂说法**　AIAC 2.0 演示将候选、研究过程和 Notebook 对应起来。可复现的 Notebook 要记录核心输入、设置、表达式来源和评估办法。课上讨论了按组合弱项选候选，示例包括控制高换手。
