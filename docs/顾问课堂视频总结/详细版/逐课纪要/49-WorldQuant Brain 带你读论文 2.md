## 第一段：让生成与实际结果对得上

讲师把工作流拆为生成、派发、监听和管理。生成时保存表达式、设置和假设 ID。派发后记录实际获得的任务 ID，监听阶段用 ID 关联状态与结果。用实际返回的绩效更新记录。批次乱序结束时按 ID 回填，避免把表现归到错误的表达式。

| 阶段 | 留档产物 | 排错时看什么 |
| --- | --- | --- |
| 生成 | 候选清单、完整 Settings、去重指纹 | 公式是否实现了写下的假设 |
| 派发 | 批次和可观察的任务、子结果 ID | 有无已知 ID 或缺失状态 |
| 监听 | 返回时间、状态、失败类型 | 本仓库异常冷却后只读对账一次 |
| 管理 | 实测结果与表达式的对应 | 比较时用同样本或明确记录差异 |

## 第二段：把盈余惊喜写成可测试的事件

1. 把论文的变量写成三列：公告实际值、公告前能够取得的预期值、预期误差如何度量。标明财报期、单位和可用时间。若论文用的是营收，不能把 EPS 当作等义代理。
2. 用 Dataset 描述缩小搜索范围，继续核对 Data Field 的具体定义。AI 可帮忙提取检索词，使用前仍需对照目标 Region、Universe 和 D1 的可选字段。
3. 单独记下公告附近的短期反应与更长时期结果。先跑主信号，再增加规模、成长或情绪条件，对照是否只是改变了样本范围。
4. 用实际 Alpha 结果做记录，同时保留未改善和未观测的候选。课程问答中的示例和作业条件按当时理解。
