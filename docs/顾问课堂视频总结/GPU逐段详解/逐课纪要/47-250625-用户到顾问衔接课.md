讲师在〔语音 00:18:00〕中提到，当阿尔法策略在不同市场（如ASI、euro、global）中表现时，需注意margin（保证金）的使用。尤其在市场流动性较低时，需谨慎提交阿尔法策略。这表明在成为顾问后，需关注不同region（地区）的市场特性，因为universe（投资组合）会随着region的变化而变化。  

### illiquid Universe的特性  
〔语音 00:18:30〕中提到，illiquid（流动性差）的universe会带来额外的风险。这类市场通常流动性较差，因此在进行数据核查时，需特别关注这些universe的特性。同时，delay（延迟）在不同universe中是相同的，但流动性差的市场可能影响回测结果的准确性。  

### 中性化功能的扩展  
〔语音 00:19:00〕中讲师强调，成为顾问后，中性化（neutralization）功能将更加丰富。除了现有的industry（行业）、sector（子行业）等中性化方式，还将支持country（国家）和更复杂的分风险中心化（risk centerization）。这为数据核查提供了更多维度，例如通过中性化去除市场风险。  

### 风险中心化的概念  
〔语音 00:19:30〕中讲师提到，风险中心化（risk centerization）是将投资组合中的风险因子（risk factor）进行中心化处理，以去除与风险相关的部分。这有助于更准确地评估阿尔法策略的纯收益。  

### 风险因子的内置与应用  
〔语音 00:20:00〕中讲师指出，系统已内置了多种风险因子，用户可以通过中心化方式去除这些因子对pnl（盈亏）的影响。这为数据核查提供了新的工具，例如通过中性化后的pnl来验证阿尔法策略的有效性。  

### 风险中性化Alpha的文档  
〔语音 00:20:30〕中讲师提到，关于risk neutralized alpha（风险中性化阿尔法）的详细计算方法和概念，可在learn document（学习文档）中找到。这为数据核查提供了理论依据，确保策略符合中性化要求。

### 数据字段来源限制  

在课堂中，讲师强调了数据字段来源的重要性。他指出，**所有数据字段必须来自于同一个数据集**，这是构建一个合法Alpha的基本要求。例如，如果某个字段来自fundamental数据集，而另一个字段来自price数据集，那么这样的Alpha将不被视为Atom Alpha。  

讲师提到，**数据字段的来源限制**是平台为了防止过拟合（overfitting）而设置的规则。如果使用了不同数据集的字段，可能会导致模型在特定时间段表现良好，但在其他时间段表现不佳，从而影响实际交易效果。  

### 常见豁免字段  

讲师还提到，**一些常见的group字段**，如industry、country、sector、market、exchange等，是被豁免的，**不计入数据集数量限制**。这意味着，即使这些字段来自不同的数据集，也不会影响Alpha的分类。  

例如，如果一个Alpha使用了industry字段和price字段，那么industry字段不会被视为来自不同数据集，因此不会违反数据字段来源的限制。  

### 提交后的标签  

当Alpha提交后，系统会自动识别其是否符合“Single Dataset Alpha”的标准。如果符合，**页面上会出现“Single Dataset Alpha”标签**。  

讲师指出，这样的Alpha虽然在检测机制上有所放松，例如不再要求通过IS Ladder Testing，但仍然需要通过最近两年的Year Sharpe检测。  

### 失败原因与验证方法  

如果Alpha提交后被拒绝，可能的原因包括：  
1. **使用了不同数据集的字段**，例如同时使用了fundamental和price数据集的字段。  
2. **未正确使用豁免字段**，例如误将industry字段视为来自不同数据集。  

**验证方法**：  
- 检查Alpha中所有字段的来源，确保它们都来自同一个数据集。  
- 使用平台提供的字段分类工具，确认每个字段的数据集归属。  
- 查看提交后的标签，确认是否为“Single Dataset Alpha”。  

### 复验建议  

建议用户在提交Alpha前，使用平台的字段分类功能，逐一核对每个字段的数据集来源。如果发现字段来源不一致，应调整Alpha的表达式，确保所有字段来自同一数据集。此外，可以参考平台提供的豁免字段列表，合理使用这些字段以避免不必要的限制。

〔语音 00:38:00〕 中，讲师建议用户在提交PPAC Alpha时，需确保数据质量。具体要求包括：

〔语音 01:18:30〕 中提到，**所有Alpha的performance** 是指用户提交的所有Alpha的综合表现，不考虑交易成本。而 **after cost performance** 是指在扣除手续费后的表现，即 **aggregated data**。  

讲师指出，**after cost performance** 更具挑战性，因为它反映了实际交易中的成本影响。因此，用户需要特别关注这一指标，以判断自己的Alpha是否在实际交易中能带来正收益。

讲师进一步解释，**负的margin** 表示用户在实际交易中可能无法覆盖手续费，导致Alpha亏损。因此，用户必须确保自己的Alpha在扣除成本后仍能保持正收益。  

### 〈数值待核〉. Alpha筛选机制  

〔语音 01:19:30〕 中提到，平台会对用户提交的所有Alpha进行筛选，选出部分Alpha进行二次评估。这种筛选机制为用户提供了“二次机会”，即使某些Alpha表现不佳，也可能被平台忽略。  

讲师指出，**combined selected alpha performance** 是平台筛选后的表现，而 **no matching alpha refresh** 表示当前没有Alpha被选中。用户需要关注这一指标，以判断自己的Alpha是否符合平台的筛选标准。  

### 〈数值待核〉. Alpha性能的最高值  

〔语音 01:20:00〕 中提到，平台会取用户所有Alpha的最高性能值进行评估。例如，如果一个Alpha的performance是负数，而另一个是正数，平台会取正数作为评估依据。  

讲师强调，**取最高值** 是平台评估Alpha性能的一种方式，用户需要确保自己的Alpha在这一评估中符合要求。

### 〈数值待核〉. 六维评估机制
