# 相关性与组合

## 先写明比较对象

| 读数 | 被比较的对象 | 使用条件 |
| --- | --- | --- |
| 本地 SC 初筛 | 候选 Alpha 与同 Region 的个人历史 Alpha PnL | 记录池版本、样本跨度、日期交集和最大相似项 |
| 候选池两两相关性 | 同一研究批次或组合中的候选之间 | 记录候选对、剔除或保留理由 |
| Power Pool Correlation | 对应 Power Pool 比较池 | 带上类别、当期主题和实际检查项 |
| Production Correlation | 平台定义的生产池 | 使用当前可归属的数值响应，分开记录状态和结果 |

本地初筛节约昂贵的平台检查。对齐日期并核对序列口径，避免将累计曲线与日收益直接互比。缺样本、常数序列或结果为空时保留不可判定状态。查看最相似的一项时，也核对表达式族、持仓与收益时段。换 Region、比较池或共同日期后，相关值的可比范围随之变化。来源 [第 47 课 00:46:50–00:48:21](<../../原始转录/47-250625-用户到顾问衔接课.txt>)、[第 53 课 01:13:43–01:16:51](<../../原始转录/53-250524-Consultant Training-Part 2.txt>)。

## PC 的状态与门槛

HTTP `200` 空体、`all_passed: true` 无检查明细、`null` 或 `PENDING` 都缺少可裁决的数值。仓库将相关性空体标为 `PENDING_PC_COMPUTING`，用项目的 `pc_poller.py` 查真实状态。RA、PPA 适用门槛从项目真源读取。若界面报 `Prod Correlation FAIL` 而没有有效的 PC 数字，检查实际项目、PPA 优先路径和失败项，再下结论。低 PC 只证明对应相关性关口的结果，后续判断还要带上基础和风险指标。来源 [项目 AGENTS.md](../../../../AGENTS.md)、[PC 轮询实现](../../../../wq_research_v2/src/wq_research_v2/pc_poller.py)。

## Super Alpha 的最小验证

1. 固定 Combo 比较 Selection，分别标记候选资格、Selection Handling、排序方向和入池上限。观察实际入池数量与底层候选分布。
2. 固定同一入选池和 Settings 再比较 Combo。记录权重集中、相关性、分年 PnL、换手和 Margin，找出一段变化能归因到哪些底层 Alpha。
3. 课堂的可复现实例是 **Selection `turnover`、Combo `1`**，画面为 USA / TOP3000 / D1、Positive、Selection Limit 10。该例从符合条件的候选里选择换手最高的十条，Combo 给每个入选 Alpha 相同的组合分数。它用于验证过滤、排序和组合赋权，结果有无增益仍依赖比较。来源 [第 42 课 00:40:30 原图](<../../详细版/画面/42/00-40-30-frame-122.jpg>)、[第 42 课 00:40:24–00:40:56 口述](<../../原始转录/42-super alpha第一节.txt>)。

## 组合目标如何取舍

给候选写清它是补一个新方向、提高利润效率、降低组合集中，还是改善某个时期的表现。第 09 课以 Sharpe 与 Margin 的取舍说明目标跟现有组合和研究阶段有关。按工作区执行时先满足当前硬门槛，再按项目指定优先级排序并留档。来源 [第 09 课 00:36:01–00:38:07](<../../原始转录/09-260113-Ready_for_Genius!.txt>)。
