# 研究工作流与 AI

## 验收 AI 生成的成果

| 交给 AI 的任务 | 验收材料 |
| --- | --- |
| 找字段 | 能定位 Dataset 和具体 Data Field，带定义、类型、可得时间和当前 Region／Universe 的覆盖证据 |
| 生成模板 | 先说假设与失效条件，再给可读槽位。抽查实际展开的表达式、允许算子、参数和 D1 Settings |
| 从历史模板增强 | 保留母版与变体的对应关系。固定设置，比较母版与单项改动，以实际回测决定改动是否有价值 |
| 写 Notebook | 把环境版本、输入清单、轴、运行顺序和输出写齐。独立运行后的真实结果才用于比较 |

## 批次和续跑

1. 生成阶段记录假设、表达式、完整 Settings、指纹和原始顺序。抽样时保留候选清单版本和种子。用带 Settings 的批次文件验收导出是否齐全。
2. 派发、观察完成情况和落盘分别记录。批次 ID 和子结果 ID 将输入关联到真实结果。请求结束、界面显示进度与子结果实际可查询是不同状态。
3. 续跑优先根据原清单指纹和已观察结果重建剩余集合。旧位置只适用于同一份输入及同一顺序。统计有效结果、确定的失败和未观测结果，保留分布。
4. 本项目遇 `429`、`5xx`、超时或缺子 ID 时存指纹，标 `PENDING_RECONCILE`。冷却后只读对账一次。若仍未观测，保留 `RESULTS_UNOBSERVED`。已有完整结果按项目台账规则保留。生产回测模式、并发边界和平台写操作按当前项目约束，历史课堂的 QUICK 建议不能替代项目的 FULL 方案。
