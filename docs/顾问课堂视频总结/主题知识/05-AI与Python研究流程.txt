05  AI 与 Python 研究流程

本篇把课堂示例整理成一条可复跑的 D1 研究路径。条目中的视频编号对应逐课纪要和原始转录的同名编号。

一、先写研究问题，再让模型给候选

把问题写成一句可验证的假设，例如「某类公告意外是否有一段可观察的后续反应」。列出事件何时可用、预期信号方向、证伪条件，再说明 Region、Universe、Delay=1、数据来源和可用的算子。可用一组固定假设对照不同 Dataset，或固定数据集对照不同假设。

先用 Dataset 描述缩小范围，再核对 Data Field 的口径、可用范围、原值、频率、覆盖和类型。向量字段要有明确的聚合规则。让模型引用官方 Learn、Data Explorer 或本地实测记录，先拿一个能查到条目的问题测引用，再拿资料没覆盖的问题测它是否会猜。字段 ID、算子签名和时间窗以原条目核对。

二、把概念、模板、具体表达式做成可对照的输入输出

让模型按结构返回研究假设、字段、算子、表达式与经济解释。Notebook 可以用 Pydantic 约束字段类型，代码只接收能通过校验且在当前 Region / Universe / D1 配置下可用的组合。保存模型版本、提示词、字段清单及模板版本，方便重跑。

概念说明和实现示例成对保留。把字段绑定和表达式展开交给小而确定的模板函数，有含义的字段槽位先各自限定范围。同一语义的候选可以先少量展开并验证，确认语法、维度、方向和设置，再按明确假设增加样本。换字段或改窗口时尽量一轮只改变一项，并记录那一项为何值得试。

三、移植到 Python Alpha 时先核对逐日输出

先用少量已知日期和证券复现最小基线，逐日核对时间、证券索引、向量方向与权重。Fast Expression 和 Python 的实现细节可能不同，把分组、缺失值、窗口边界以及使用何时可见的数据写明。确认差异来源后再比较表现。

把数据与每天调用之间需要保留的状态分清楚。模型训练、验证、独立测试按时间划分，验证区间可以选择参数，独立测试留到方案确定后检查。若研究在线更新，记录标签何时可观测、更新时间和该时点可用的数据。常规研究配置始终使用 D1，录屏中的 Python 数据类型和运行环境仍应以平台实际文档核实。

四、把生成、派发、监听与落盘分开

生成的候选先入现有候选池，再按优先级领取小批。保存表达式与设置的指纹，记录任务 ID、子结果 ID、状态、错误、耗时和实际观察到的结果。完成顺序可能与派发顺序不同，按 ID 更新。利用同假设的整批分布对照基线，保留可复核的正例、失败例和结果缺失项。

断点续跑以原始 Expressions with Settings 文件、原顺序和日志一起核对。改文件或再次打乱顺序后，按指纹和已观察结果重建剩余项。若终端仅显示已推送，继续核对平台是否确实有结果，用实际状态更新记录。

五、异常时执行项目的只读对账规则

遇 429、5xx、超时或缺少子 ID，保存指纹及已知 ID，标为 PENDING_RECONCILE。冷却后仅查询一次，取得结果才更新状态，仍未观测则落 RESULTS_UNOBSERVED。相关性 HTTP 200 空体进入 PENDING_PC_COMPUTING，按项目轮询器查询真实结果。在一轮研究中保留所有已观察结果，RA 与 PPA 分开记录和检查。

六、把复盘和研究日志变成下一轮的输入

同一轮保存种子和基线、Region / Universe / D1、字段来源、改动理由、结果与剩余问题。把一项有益调整、一项失败调整及它们的适用条件一起反馈给模型，并说明下一轮的验证范围和停止条件。定期用日期锚定日报，写明哪些结果已观测、哪些待检查、今天要验证哪项假设。工作流先手工跑通，再在新会话用同一份说明复跑，核对输出能否追到数据。

复现 Notebook 保留环境依赖、输入清单、生成步骤和结果对应关系。账号口令与模型凭据留在其授权配置中。课程里出现的比赛额度、奖励、评分权重以及提交材料细则属于各自录制时的安排，实际参加活动时核对当期规则。
