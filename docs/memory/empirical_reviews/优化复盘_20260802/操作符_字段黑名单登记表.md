## 先看结论

- **操作符：只记录，不淘汰。** 操作符失败不能触发“拉黑操作符”或强制更换操作符。
- **字段：200 个有效因子仍无完整通过，才标记** `FIELD_VERDICT = GARBAGE_CANDIDATE`。
- **数据集：多个字段达到正式垃圾字段标准后，才汇总标记** `DATASET_VERDICT = STOP_DATASET`。
- 当前历史记录没有足够的统一计数证据证明任何字段已经达到 200；目前的 `STOP_EARLY` 是节省回测预算，不是正式拉黑。

## 明显状态标签

| 标签 | 含义 | 是否计入 200 |
|---|---|---:|
| `ACTIVE` | 仍可探索 | 是，若结果完整 |
| `STOP_EARLY` | 已出现明显失败模式，暂时停止扩展 | 否，除非继续补齐有效计数 |
| `SYNTAX_ERROR` | 表达式或参数写法错误 | 否 |
| `PENDING` / `RESULTS_UNOBSERVED` | 平台结果未观察到 | 否 |
| `FIELD_VERDICT = GARBAGE_CANDIDATE` | 该字段达到 200 个有效失败因子 | 达标后停止 |
| `DATASET_VERDICT = STOP_DATASET` | 数据集内字段失败已达到停止依据 | 停止数据集 |

## 每个字段的唯一计数格式

```text
[FIELD-LEDGER]
dataset_id=DATASET-XXXX
dataset_name=<数据集全名>
field_id=FIELD-XXXX
field_name=<数据字段全名>
operator_id=OP-XXXX
operator_name=<操作符全名>
alpha_id=<平台 Alpha ID>
expression=<完整表达式>
status=VALID_OBSERVED | PENDING | RESULTS_UNOBSERVED | SYNTAX_ERROR
base_gate=PASS | FAIL
failure_reason=<明确指标原因>
valid_count_for_field=<当前字段有效因子数>/200
field_verdict=ACTIVE | STOP_EARLY | FIELD_VERDICT = GARBAGE_CANDIDATE
dataset_verdict=ACTIVE | STOP_EARLY | DATASET_VERDICT = STOP_DATASET
next_action=<继续该字段/换字段/停止数据集>
```

## 正式判定顺序

1. 先确认 Alpha ID、完整指标、无平台待定状态，再计入该字段的有效因子数。
2. 同一表达式重复创建不重复计数；仅换一个无意义参数也不算新的策略风格。
3. 字段达到 `200/200` 且没有完整通过者，才写入 `FIELD_VERDICT = GARBAGE_CANDIDATE`。**特殊情况：如果发现大批量的字段为厂字（count = 0, pnl flat），直接拉黑这个字段/数据集。**
4. 同一数据集内的字段正式判定结果汇总后，才决定 `DATASET_VERDICT = STOP_DATASET`。
5. 操作符始终只记录，不能因为操作符表现差而拉黑；每 10 个有效批次复盘字段计数和数据集多样性。
