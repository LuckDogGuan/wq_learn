一句话看懂您上传的《PPA 与 RA 提交检查何时运行》流程图：系统不是看你起的 Alpha 名字，而是只要结构简单（≤8 算子、≤3 字段），点检查时就自动先跑 PPA 检查；PPA 没过才退回跑 RA 检查。所以只要把 RA 与 PPA 两条线分开管，就不会被系统的混合报错绕晕！

避坑 1 · 看到 “Prod Correlation FAIL” 不一定是 PC 挂了！

当一个简单表达式先跑 PPA 检查、因 PPA 池自相关 > 0.50（且 Sharpe 没高出 10%）失败后，系统会回退去跑完整 RA 测试；如果 RA 也挂了，页面最终可能显示 Prod Correlation FAIL。根因其实是 PPA 池自相关！

避坑 2 · 去掉 PowerPoolSelected 标签并不会移出 PPA 池

PowerPoolSelected 只是提交后的榜单组合标签。哪怕去掉该标签，该 Alpha 依然留在 PPA 自相关池中，新提交的 PPA 仍会和它算 < 0.50 相关性。

避坑 3 · Pure PPA 必须配满 4 个硬条件

① 英文描述 ≥ 100 字符；② 必须匹配当期 Thematic Power Pool 主题（国家级 RA 主题无效，且非主题区部分 PPA+ATOM 也会被当 Pure PPA 拦截）；③ 使用合规风险中性化；④ 满 3 个月后每榜单限 ≤1/天、≤10/月。

好消息 · 简单表达式同时过 RA 门槛 = 自动免费 Hybrid

我们 RA 主线主打的 2–4 算子极简因子，虽然结构上也会触发 PPA-first 检查，但只要它通过了完整 RA 标准：① 若 PPA 也过 → 自动以 Hybrid (PPA+RA) 提交，且不占 Pure PPA 配额；② 若 PPA 没过 → 自动退回按正常 RA 提交成功！因此专心把 RA 主线做扎实完全安全。
