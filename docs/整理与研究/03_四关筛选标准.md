## 零阶前置闸门（0 回测或低消耗，执行于第一关之前）

吸收 `2026Q4` Top 100（`JX14975 #100`、`JR23144 #12`、`ZS59763 #32`）与 `worldquant-experience-reuse` 实证经验，避免把额度浪费在坏字段上：

1. **硬参数校验**：强制断言 `settings.delay == 1`；禁止在表达式中使用本 Gold 账号无权限算子（如 `ts_median`）或写错签名（如 `hump(x, hump=0.01)` 必须关键字传参、API 中性化必须传 `REVERSION_AND_MOMENTUM` 而非 `RAM`）。
2. **`datecoverage` 与有效年限预筛（`JX14975 #100`）**：核查字段元数据覆盖率与日期覆盖，**禁止将 IS 有效数据不足 5 年或尾部严重缺失的字段送入正式提交候选**。
3. **伪 VECTOR 识别（`JX14975 #100`）**：对日内仅 1 个元素的“伪装成 VECTOR 的单值字段”（`vec_avg/sum/min/max` 差异 `<2%`），仅测 `vec_avg`（避开 `vec_sum` 防 OS 漂移），跳过无意义聚合枚举，直接节省 ~80% 额度。
4. **厂字型秒杀标准（`ZS59763 #32` / `JR23144 #12`）**：回测返回后若**有效非零 Sharpe 年份 `< 8` 年**，或出现**连续 `≥ 200–250` 天相同非零 PnL / 全平直 PnL**，直接判定为厂字型死信号，立即剔除并登记 `FAST_DEMOTED`。

## 第一关 · 简单表达式找信号（`IS Sharpe > 0.8`）

- **实验设置纪律（`ZS59763 #32` / `LD22811 #13`）**：
  - 锁定 `Region × Universe × Delay=1`，**初筛期固定 `decay = 0`、单一中性化（如 `INDUSTRY` 或 `SUBINDUSTRY`）**，严禁在第一关做 `Neut × Decay` 笛卡尔积扫参。
  - 通常 **1 个底层字段 + 1 个核心变换**（如 `rank(x)`、`ts_rank(x, d)`、`ts_delta(x, d)`）；VECTOR 先选明确聚合口径（`vec_avg / vec_sum / vec_count / vec_min / vec_max`）。
- **晋级与方向翻转**：
  - 取得可归因有效回测与唯一 `Alpha ID`，**`IS Sharpe > 0.8`**（且非厂字型）即进入研究候选池，保留原式为基线。
  - 若 **`IS Sharpe < -1.2`**（王哥自动翻转阈值），单立一条取反实验 `-1 * (expr)`（加防递归死循环标记，显式锁定方向符号，防 `qMNZ9aMA` 式符号丢失事故）。
  - 优先参考 **`SZ83096 #47` 2Y 健康度观察**：若全期 `> 0.8` 但最近 2 年收益彻底崩溃，标为 `2Y_WEAK_WATCH`，在第二关优先验证原因而非盲目堆平滑。
  - T0 模式校准确认后，第一关可用 `simulationMode="QUICK", visualization=false` 加速探针，但须与 Full 有效完成量分账统计。

## 第二关 · 筛收益，再单变量逐项改善（不强跳 1.58）

> **核心纪律**：每轮**仅修改 1 个变量**（只加一层表达式，或只调 1 个参数/设置），严格留存同口径基线；**禁止在第二关要求一步跳到 `Sharpe > 1.58`**。

| 阶段 | 检查与单变量动作 | 保留 / 晋级判据 |
| --- | --- | --- |
| **2A · 筛有效收益与风险中性健康度** | 核查持仓数、覆盖、全期 Returns、年度与固定测试期（Test Period）PnL、以及 **2Y Sharpe 与风险中性（RN）表现**（USA D1 80 批历史复盘显示，2Y 与 RN 崩塌是首要死因）。 | 排除全期 `Returns ≤ 0` 或厂字型；全期为正且有可解释收益进入 2B；仅单一时期有效标待查。 |
| **2B · 结构优化先行** | 先不乱拉 Decay，优先用结构手段补强信号：同向极值对齐（`vec_min`/`vec_max`）、`min(rank(x), rank(y))` 双强组合、嵌套分组（内层行业 + 外层国家/区域救 Sub-universe）、`ts_backfill` 补稀疏。 | 目标短板改善且保住 2Y/RN 收益即升级为新基线；出现收益与换手等取舍时**并存两版**供下一轮对照。 |
| **2C · 换手、分布与区域 Margin 微调** | ① 换手偏高（如 `>30%`）：分别单独试小步平台 Decay（`0→1/3/5`）、`ts_mean`、`ts_decay_linear`（**警惕 `dense=false` 拉偏 `[0,1]` 排名**）、`hump(x, hump=0.01)` 或高 TVR 算子（`ts_target_tvr_decay` 须 `lambda_max ≤ 1`）；② 关注**区域 Margin 经验底线**（`USA≥5bp, GLB≥9bp, EUR/AMR/HKG/JPN/KOR≥10bp, ASI≥15bp, CHN≥20bp`，注意 API 返回小数 `0.01=100bp`）；③ 尾部或权重集中：单测 `winsorize`、`Truncation`、`Max Trade` 或 `Max Position`（USA/ASI/EUR）。 | 保留可复现改善且不破坏 2Y/RN 收益的候选；平滑绝不能以牺牲 2Y/RN 为代价（如 `GreR9PXG→KPE1Z3zk` 反例）。具备可复现改善证据后进入第三关。 |

## 并行本地 SC · 全程同步跟进（绝不等待终检才算）

- **触发时机**：① 第一关 `IS Sharpe > 0.8` 入池；② 第二关保留任何有收益变体；③ 第三关生成新的 `Alpha ID`。由 `wq_research_v2/sc_local.py` 与实验并行计算，不阻塞回测槽位。
- **计算口径与红线**：
  - 使用最新完整日收益序列（先同步补齐当前全部 **92 条** OS Alpha，修复旧 `sc_engine.py` 滞后 2.5 个月且剔除 23 条 PPA OS 的隐患），与同地区本人已提交 Alpha 对齐日期求最大 Pearson 相关系数（同时计算**候选池内两两 SC 矩阵**，落实 `JR23144 #12` 防“交一个挂一批”）。
  - **王哥本地安全线 `≤ 0.68`**（预留 ~2% 截取误差），平台官方硬线 `< 0.70`（若 `≥ 0.70` 须 Sharpe 比最高相关已提交 Alpha 高 `≥ 10%`，以平台实判为准）。
- **反假零铁律（修复旧 `sc_engine.py` Bug）**：
  - 当本地缓存过期、目标区域无已提交参考池（如当前 `DEU / ASI / CHN` 空白区）、或无有效日期重叠/`NaN` 时，**严禁返回 `0.0`**！必须显式返回结构化状态 `NO_PEERS_IN_REGION`、`CACHE_STALE` 或 `PENDING_NO_OVERLAP`，并在记录中标明参考池样本数与重叠天数。
  - 高 SC 但收益强的变体保留证据，转入专门的降相关通道（如 `signed_power`、`bucket(rank(x))` 分组或换信号假设）。

### 3.3 第三关末期稳健性与精简必做工序（`ZS59763` / `ZH87224` / `JX79797`）

在基础检查全部通过后、查远程 PC 前，对候选做轻量稳健性体检：
1. **算子消融化简（`ZH87224 #51` / `ZS59763 #32`）**：逐一试拆冗余 `ts_backfill`、`winsorize`、`abs`、`+0.01`，在无损性能下压低算子数（目标 `< 6` 个，优化 Genius Tiebreaker `Avg distinct Operators/Alpha`）。
2. **Decay 防断崖压力测试（`ZS59763 #32`）**：在 `[0, 1, 3, 5, 10, 20]` 检验邻近表现；若小增 Decay 即断崖下跌，标为超短期过拟合警示。
3. **Neutralization 局部稳健性复核**：仅对已过基础门槛的候选核查邻近中性化（如 `INDUSTRY`/`SUBINDUSTRY`/`REVERSION_AND_MOMENTUM`/`STATISTICAL`/`CROWDING`），避免单一参数孤岛。

**Tier-1 过关判据**：独立于相关性的适用 D1 必过项 `FAIL == 0` 且无阻断级 `WARNING`，方可进入第四关。

## 第四关 · 远程 PC 与 `Alpha Pre-Submission Check` 终检（Tier-2 门禁）

- **PC 唯一权威来源**：**只采 BRAIN 远程 `/alphas/{id}/correlations/prod` 数值结果**。常规硬线 **`PC < 0.70`**（临界例外：比最高相关 Alpha 的 Sharpe 高 `≥ 10%`，以平台 `get_submission_check` 实判为准）。
- **防误判状态机（修复旧 `sim_api.py` 与经验库雷区）**：
  - 严禁把 `200 空体`、空 `checks` 下的 `all_passed=true`、`float(None)` 或 `OS=0` 误判为 `PC=0`！
  - `200 空体` 标为 `PENDING_PC_COMPUTING` 进有界退避异步队列；`429` 按头退避；拉取到确切数值且 `get_submission_check` 全部必过项为 `PASS` 才算完成。
  - 若仅因 `PC ∈ [0.70, 0.75]` 失败，可回第二关单测 `SZ83096 #47` 的 **`signed_power(x, p)` 保序降 PC** 或王哥的 `bucket(rank(x))` 分组降 PC。
- **人工复核移交**：终检全过的候选汇总 `Alpha ID`、完整表达式与设置、本地 SC（含参考池口径）、远程数值 PC、全部 D1 `is.checks` 及 `Idea + Rationale`，状态标为 **`CANDIDATE_FOR_MANUAL_REVIEW`**。**系统永不调用 `submit_alpha`（`Formal Alpha Submission`）**，由用户在 BRAIN 平台亲自复核并决定正式提交。

## 附录 · D1 Power Pool 支线标准（仅用于 `ASI/D1` 等 D1 Theme 支线，与主线 RA 分账）

- **硬门槛**：`Delay = 1`、`Sharpe ≥ 1.0`、总算子 `≤ 8`（`ts_backfill` 与 `group_backfill` 不计入）、独立字段 `≤ 3`（不含 7 个分组字段）、`PPAC < 0.5`（或 Sharpe 高 `≥ 10%`）、Turnover / Sub-universe / Robust-universe 全通过、提交必填 `≥ 100` 字符 `Idea + Rationale`。
- **配额豁免铁律（`7GNvo8y` 2026-11-09 公告）**：纯 PP 受“每日 1 个、每月每域 10 个”限制；但 **`Power Pool + ATOM`（单数据集）或 `Power Pool + Regular` 完全不受上述配额限制**。因此 ASI/D1 支线**强制优先构造单数据集（ATOM）PPA**。
- **Quick 模式陷阱提醒**：Quick 模式按 Regular 标准判定，合规的 `1.0 ≤ Sharpe < 1.58` PPA 在 Quick 下会显示 `FAIL`，必须看数值而非仅看通过标记，复核一律走 `Full`。
