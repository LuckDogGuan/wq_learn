## 1. 核心冲突与实战裁决对照矩阵

| 维度 / 机制 | 开源矿机系统 (`src/worldquant-miner`) | 生产实证经验库 (`doc/总结`) 与 用户硬约束 | 深度裁决理由与实战依据 |
|:---|:---|:---|:---|
| **禁用算子** | 大量使用 `add`, `multiply`, `trade_when`, `+`, `*` 等裸代数算子 | **【绝对禁止】** 严禁使用 `trade_when`、`add`、`multiply`；算子总数严格限制在 `< 8` | 裸加乘破坏量纲并在极值点产生尖峰共振，100% 击穿 `CONCENTRATED_WEIGHT` 门禁；`trade_when` 造成逻辑分支不连续与阶梯夏普断崖 |
| **Alpha 提交控制** | 包含自动提交脚本逻辑 (`submit_alpha`) | **【绝对禁止自动提交】** 任何情况下严禁调用 `submit_alpha`，必须由研究员在 Web 端手动点击提交 | 提交是不可逆的平台履约行为，自动化静默提交会导致劣质因子污染账户信誉并触犯第十条量化铁律 |
| **回测调度方式** | 单任务 `create_simulate` 或无序 Python 多线程并发 | **【强制 8 并发批次回测】** 必须使用 `multi_create_simulate` (8 并发)，严禁单任务回测 | 平台对单点 API 有严格频控（Rate Limit），8 并发批量接口是唯一被平台原生支持的高吞吐稳定通道 |
| **相关性标准** | 容忍相关性高达 0.70 ~ 0.75，缺乏多因子正交要求 | **【极其严苛双相关性】** 挖掘出的不同因子彼此间相关性 `< 0.40`；生产相关性 `PROD_CORRELATION < 0.70`（未出结果一律禁止提交） | 相似度过高的因子无法点亮不同金字塔，且自相关超标将导致批量被拒并扣减算力权重 |
| **数据源质量过滤** | 随机选取 `fundamental6`, `analyst4` 等少数默认数据集，盲目扫描 | **【离线数据质量审计】** 强制使用 `webdata_quality` 预先过滤 T1/T2 健康档位、5 ≤ Count < 500 的未点亮金字塔冷门特征 | 数学无法弥补物理稀疏，盲目尝试已被数百人挖掘过载的高拥挤数据集只会徒劳引发 `MATCHES_THEMES` 拦截 |
| **单票集中度防御** | 试图通过 `truncation=0.01` 暴力解决集中度报警 | **【先平滑后组合 / 纯净单字段】** 优先使用 1~2 个字段，算术前强制 `ts_decay_linear` 平滑并套全局 `rank() - 0.5` | 当有效覆盖股票数不足时，1% 的硬截断仍会因“组合有效持仓标的数严重不足 (Insufficient Breadth)”而直接判定集中度失败 |
| **风险中性化深度** | 仅评估 Raw 夏普与收益率，无视风格剥离 | **【强制风险中性化审计】** 必须达成：RN Sharpe > 1.0, RN Fitness > 0.7, RN Margin > 5bp | 任何未经多因子风险模型检验的虚假高夏普，本质只是裸暴露未对冲行业风险敞口的“毒丸” |
| **换手与利润垫门禁** | 仅要求换手率 < 70%，无 Margin 硬要求 | **【严格换手与利润垫走廊】** Turnover 严格落在 `5% ~ 30%`；Margin 必须 `> 5 bps` | 换手低于 5% 容易钝化失效，高于 30% 则在实盘中被摩擦成本绞杀；Margin < 5bp 实盘必死 |
| **地区与股票池配置** | 默认采用 USA TOP3000 / INDUSTRY 中性化 | **【深度适配地区微观结构】** EUR 大区优先使用 `TOPCS1600`（通关率 89.6%）+ `SUBINDUSTRY` 中性化 | EUR TOPCS1600 精准剔除泛欧 900 只僵尸股，子行业中性化极其纯净，主题冲突率骤降 40% |
| **数据集切换纪律** | 遇到挫折即高频随机切换数据集 | **【深耕未点亮金字塔单数据集】** 严禁频繁切换数据集，除非该模板多样性已穷尽且查阅论坛仍无计可施 | 频繁跳跃会导致每个数据集浅尝辄止，无法在特定金字塔数据集内摸透时序与截面微观结构 |

## 2. 矿机反模式的深度根因复盘

### 2.1 算子滥用之祸：`trade_when`、`add` 与 `multiply`
- **`trade_when` 的伪信号陷阱**：  
  `trade_when(condition, alpha, 0)` 在很多回测中看似能够规避特定行情，但其实质是引入了强阶跃式的时间断点。当条件不满足时组合仓位骤变，导致短期换手率飙升至数百百分点，且极易引发样本外阶梯夏普（`IS_LADDER_SHARPE`）瞬间归零。
- **裸 `add` / `multiply` 的集中度刺客**：  
  在真实世界数据中，两张表的数据分布极少呈现完美对称高斯分布。未对齐量纲的 `add(A, B)` 会使具有较大绝对方差的字段 $A$ 完全吞没字段 $B$；而 `multiply(A, B)` 更是非线性极值放大器，两数相乘瞬间制造出 $+10\sigma$ 的离群巨兽，导致多头端单票资金配额穿透 10% 红线。

### 2.2 盲目爬山的“打地鼠”死循环
原矿机在发现因子集中度失败后，通常盲目加入 `winsorize` 或调低 `truncation`，但这又导致因子方差被过分压缩，夏普比率跌破及格线。  
**解药只有一条**：严格遵循 `doc/总结` 归纳的“短窗时序提取 + 适度线性衰减（如 `ts_decay_linear(ts_zscore(field, 20), 10)`）”，保持算子总数 `< 8`，以纯粹优雅的数学逻辑直击收益本质。

## 3. 全量门禁硬指标基准线 (Hard Check Baseline)

在整合矿机老虎机算法与实战经验时，所有产出因子必须硬性通过以下全绿基准测试：

```
[WorldQuant BRAIN 终审准入红线]
├── 1. 基础性能:
│   ├── Sharpe > 1.58 (Delay 1 黄金标准)
│   ├── Fitness > 1.00
│   ├── 2Y Sharpe > 1.60 (近期性能不衰退，阶梯夏普必过)
│   └── Margin > 5.0 bps (0.0005，确保充沛利润垫)
│
├── 2. 换手率区间:
│   └── 5.0% < Turnover < 30.0% (杜绝高频绞杀与超低频钝化)
│
├── 3. 风险中性化 (Risk-Neutralized):
│   ├── RN Sharpe > 1.00
│   ├── RN Fitness > 0.70
│   └── RN Margin > 5.0 bps
│
├── 4. 表达式与工程复杂度:
│   ├── 操作符数量 < 8 (精简稳健，防止过拟合)
│   ├── 严禁包含 trade_when / add / multiply
│   └── ra_failed_count == 0 (所有子项门禁零告警)
│
└── 5. 生态排他性与相关性:
    ├── 候选因子间两两相关性 < 0.40 (多策略风格正交)
    └── 平台生产相关性 PROD_CORRELATION < 0.70 (且必须等待结果产出)
```
